# 講義全体のアーク設計

講義シリーズ全体の幹と、未執筆回の仕様をまとめる。設計の根拠は [engaging-lecture-design.md](engaging-lecture-design.md)（IP3200 で効果を確認した手法）。回を追加・並べ替えたら、このドキュメントと `index.qmd`・`_quarto.yml` を同時に更新する。

## 全体構成：全14回

最終回は**手書き数字分類を PyTorch で自作**（MLP で完結。CNN は導入しない — アウトロで「この先」として1枚触れるのみ）。この枠に収めるための決定（2026-06）：

- **Newton法は参考資料に降格**（`newton-method-appendix.qmd`）。本編の最適化回は勾配降下法に専念。NN 幹で使うのは GD だけ。
- **「現代のAI」（CNN・Attention）の講義回は廃止**。最終回が現代 AI の実演を兼ねる。Attention/LLM は概論の歴史パートで触れる。
- クラスタリング・PCA は2回のまま残す（魚の物語で完成済み、14回に収まる）。

回割り：導入1（概論）＋ 分類問題と特徴量5 ＋ fit() の中身8（勾配降下法／線形回帰と正則化／NN最小単位／変換を重ねる／バックプロパゲーション／NumPy実装／PyTorch入門／手書き数字プロジェクト）。

- `ai-introduction.qmd` の冒頭で、**直線では絶対に分けられないデータを機械が自力で分けた図**（NN の曲がった決定境界）を見せ、続けて**手書き数字の格子図**で最終回の成果物を予告する。
- 宣言：「この講義の最後までに、この仕組みを**中身から全部**組み立てる。ブラックボックスは残さない」

## 設計メモ（執筆時の仕様、全回実装済み）

執筆完了後も、各回を改訂するときの設計意図のリファレンスとして残す。

### 線形回帰・多項式回帰

- 題材は実データ1本（engaging-lecture-design.md の実データ主義。気象庁の気温データ等、採用前にスパイク・形を実測で検証）。
- 構成：直線を**目で**引く → 当てずっぽうの限界 → 損失（二乗誤差）を定義 → 勾配降下で fit（最適化回の道具をそのまま使う）→ `sklearn` と答え合わせ。
- 多項式次数を上げて過学習を**起こして見せる**（クイズ：「次数を上げたら精度はどうなると思う？」→ めくり）→ 正則化。過学習と汎化の回の train/test・ギャップの読み方がここで再登場する。
- 過学習は3段構成のスレッドになっている：2次元決定境界の回で「あやしい満点」を見せる（引き）→ 過学習と汎化の回で正体を暴く（本編）→ この回で正則化という対抗手段を与える（解決）。書くときはこの接続を維持する。

### バックプロパゲーション

- コールドオープン：「多層になった瞬間、勾配の計算が大変になる。手で全部微分するしかない？」
- 2層・パラメータ数個のネットで**手計算1往復**（forward の数値 → loss → 逆向きに δ）。数値は必ずコードで検証してから本文に書く。
- `nn-multilayer.qmd` の「誤差が逆向きに流れる」スライドが伏線。ここで連鎖律として正体を明かす。

### 実装（NumPy）

- ゴール明示：「コールドオープンの図を、ライブラリなしの自分のコードで再現する」。
- `nn-single-unit.qmd` の forward / backward 関数を多層に一般化するだけ、という見せ方（新しい概念ゼロ、組み立てのみ）。

### PyTorch 入門

- 構成：NumPy 実装と**同じネットを並べて**書く（描き比べの装置）。`loss.backward()` 一発と backprop 手計算の結果が一致する瞬間が山場。

### 手書き数字分類プロジェクト（最終回）

- ゴール：概論の冒頭で予告した**手書き数字を読み取る機械**を、PyTorch の MLP で完成させる（コールドオープン回収③）。
- ネットは **MLP（全結合のみ）** — ここまでに組み立てた部品（アフィン変換・ReLU・ソフトマックス・交差エントロピー・勾配降下・backprop）だけで動くことが「ブラックボックスは残さない」の証明になる。CNN は**導入しない**。
- データ：MNIST（torchvision）。授業前にダウンロード手順を確認しておく。授業環境で落とせない場合の代替は `sklearn.datasets.load_digits`（8×8、概論の図と同じ）。
- 演出：学生自身が紙に書いた数字を読ませるデモ — **実装・検証済み**（2026-07、「自分の字は読めるのか」スライド）。検証結果：写真を素朴に28×28へ縮小するだけだと**0/10で全滅**（グレー背景が「インク」扱いになる）。コントラスト正規化＋MNIST流の前処理（バウンディングボックス切り出し→長辺20px→重心センタリング）で**8/10**（残る誤りはモデル自身の弱点で、うち1枚はきれいな画像でも誤読）。「直感は外れる」の原則の実証例そのもの。デッキのスニペットはこの検証済みコードと同一。
- 締め：「この先」1枚 — 画像が大きくなったら？（CNN）、入力が文章だったら？（Attention/LLM）— を**名前の紹介だけ**して講義全体を閉じる。

## 執筆方針の追補（2026-07-11、llm コースで確立した方針の逆輸入）

llm コースの全面リバイス（2026-07-10）で効果を確認した方針を、本コースにも適用する。

- **枚数を絞らない**：スライド枚数の上限は設けない。1つの概念には「動機（クイズ）→ 実験/図 → 組み立て → 観察」をフルに使ってよい。「one slide = one idea」は**枚数を増やす**方向に働かせる — 詰め込み1枚より分割N枚。目安：1回 18〜25枚。
- **図・コード・インタラクティブは説明負荷を下げる投資**：入れるか迷ったら入れる。特に（1）**関数は形（カーブ）を必ず描く**（式が出たらカーブも出す — sigmoid・ReLU・softmax・−log…）、（2）**ネットワークは構造図（D2）を必ず添える**（コードだけ・数式だけの部品定義を作らない。matplotlib 手組みのボックス図は D2 に置換）、（3）対話できるもの（explorer・plotly）は静止画の上位互換として積極採用。
- **torch API は初出時に挙動デモ**：新しい torch の道具（`tensor` 演算・`backward()`・`nn.Linear` 等）は、モデルの中で初めて使う前に「これをやるとこう動く」の極小入出力デモを見せる。
- **数値の出どころ**：スライドの断定的な数値・観察 callout は下の §実測ログ にあるものだけ。新しい主張はまず `tools/` で測ってログに書き、それから本文。

## インタラクティブ可視化の方針（2026-07-11）

llm コースと同じ3層構成。主役は自作：

1. **自作NNエクスプローラ（自作ツール、主役）** — `explorer/index.html`。この講義で学習させた**実重み**で動く。CDN 不要・日本語・講義用語。URL ハッシュ `#view=…` で初期ビュー指定、段階違いで複数デッキに iframe 埋め込み：
   - `#view=boundary` — 三日月データの2層NN。隠れユニットをクリックすると**その折り目線**を単体表示、全部合わせると曲がった境界。エポックスライダーで境界が育つ様子（nn-multilayer / nn-numpy / pytorch-intro）
   - `#view=draw` — 手書きキャンバス。数字を書くと MNIST 流前処理（バウンディングボックス→長辺20px→重心センタリング）を経て学習済み MLP が判定、10本の確率バー＋前処理後の28×28も表示（mnist-project）
   - `#view=weights` — 第1層の重みギャラリー（各隠れユニットが探している模様）（mnist-project）
2. **既存の公開デモ** — [TensorFlow Playground](https://playground.tensorflow.org/)（X-Frame-Options なし、2026-07-11 実測確認済み）を nn-multilayer に iframe 埋め込み。受け身にならないよう「30秒で隣に説明」タスク付き。
3. **plotly iframe（IP3200/llm 方式）** — `fig.write_html("iframes/…", include_plotlyjs="directory")` → `::: {.plotly-iframe src=…}`。`iframes/` はレンダー時に隠しセルが再生成（gitignore ＋ resources 登録）。対象：PCA の3D散布→2D射影（回せる）、損失地形の3D曲面＋GD軌跡、ローカルミニマムの引力圏。
