### k-means 自前実装（clustering-kmeans、2026-11-01 実測、2026-11-10 配列2本・データ凍結のあと再実測、`tools/measure_clustering_kmeans.py`）

デッキは sklearn を使わず、distance / assign / update / init_centroids / kmeans / sse / kmeans_best を自前実装する。2026-11-10 からデータは行列ではなく1次元配列2本（輝度と重さ、または横と縦の座標）で持ち、関数もそれを受け取る（行列は旧 sklearn 版の名残で、`axis=0`・行の取り出し・ブロードキャストを増やすだけだった。行列は（参考）scikit-learn のスライドで `np.column_stack` で作るだけ）。手順1（`init_centroids`、ランダム）と手順2〜4（`kmeans`、初期重心を受け取る）を分けたので、初期重心を固定すれば結果は毎回同じ。学生のコードの手順1は seed なしのランダムのままにし、スライドに出る出力と図は固定値で作る（下の「表示用の固定値」）。

本文の書き方（2026-11-10 著者指摘、CLAUDE.md の規約）：実行ごとに変わることは書かない。ランダムな初期値での成功率・頻度（旧「1000回中4割ほど（406回）」「4割ほど／8割ほど／ほぼ毎回」）は本文から外した。以下の頻度は、性質（「良い答えに着く保証はない」「回数を増やすほど着きやすい」）の裏付けとしてだけ記録する。乱数で作るデータは一度だけ生成してデッキに値で書き、図や本文が指す初期値は seed ではなく点の番号・座標で書く。

データ：80個の点は `brightness` と `weights` の2本。中身は前回までの Salmon 40匹 → Sea bass 40匹を `np.random.default_rng(0).permutation(80)` で混ぜた固定順。2026-11-10 に「種類のラベルと見比べる」スライドを削除した（ラベルのない回でラベルと照合するのは前提と矛盾し、後続でも使わない）ので、デッキに `y_true` はなく、種一致は測らない。同日、デッキ本文から「魚」「匹」も外した（データ1個＝点、数え方は「個」）。ツールは .qmd から `brightness`・`weights`・`bx`・`by`（山データ。スライドと Tweak 土台の2か所が同一であることを assert）・`init_A`・`init_B`・`cx_moved`・`cy_moved` を読み、スライドの1点ずつの `assign` と計測用のベクトル化 `assign` が同じ labels を返すことも確認する（450初期値）。
