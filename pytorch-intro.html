requires_grad：勾配を覚える印

  • まずいちばん小さな例で挙動を見る。\(y = x^2\) の \(x = 3\) での微分は、高校の答えなら \(2x = 6\)
import torch

x = torch.tensor(3.0, requires_grad=True)   # 「勾配を追跡せよ」の印
y = x ** 2
y.backward()                                # ← 微分はこの1行
print(x.grad)
tensor(6.)
  • requires_grad=True を付けた tensor は、自分が関わった計算をすべて記録する
  • backward() を呼ぶと、記録を逆にたどって微分が計算され、x.grad に入る
  • \(x^2\) で当たるのは当たり前？ — 次で、前回1往復ぶん手計算したネットワークに同じことをやらせる

山場：autograd が手計算を言い当てる

  • バックプロパゲーションの回とまったく同じネットワーク・同じ数値を流す
a = torch.tensor([0.3, -0.2], requires_grad=True)   # α1, α2
b = torch.tensor(0.1,  requires_grad=True)
w = torch.tensor(0.5,  requires_grad=True)
c = torch.tensor(-0.1, requires_grad=True)
x = torch.tensor([1.0, 0.5])                        # 入力（正解 y=1）

z = a @ x + b          # アフィン変換
h = torch.relu(z)      # ReLU
u = w * h + c          # 出力層
p = torch.sigmoid(u)   # シグモイド
L = -torch.log(p)      # 交差エントロピー（正解1）

L.backward()           # ← 復路はこの1行

print(f"L = {L.item():.4f}")
print(f"∂L/∂α = {a.grad.numpy().round(4)}")
print(f"∂L/∂b = {b.grad.item():.4f}")
print(f"∂L/∂w = {w.grad.item():.4f}")
print(f"∂L/∂c = {c.grad.item():.4f}")
L = 0.6685
∂L/∂α = [-0.2438 -0.1219]
∂L/∂b = -0.2438
∂L/∂w = -0.1463
∂L/∂c = -0.4875

答え合わせ

手計算（とNumPy検算）の答えは α: \((-0.2438, -0.1219)\)、b: \(-0.2438\)、w: \(-0.1463\)、c: \(-0.4875\)。 全桁一致。 loss.backward() の中身は、前回自分の手でやった連鎖律の機械化にすぎない。

なぜ自動でできるのか

  • forward の間、PyTorch は計算の履歴（計算グラフ）を記録している
  • backward() は、その履歴を逆順にたどって連鎖律を適用するだけ
  • やっていることは前回の手計算1往復と同じ：
    • 往路の途中の値を保存（だからメモリを食う）
    • \(\delta\) を出力側から掛けて貯める

学習ループ：3拍子

from sklearn.datasets import make_moons

X, y = make_moons(n_samples=200, noise=0.1, random_state=42)
X_t = torch.tensor(X, dtype=torch.float32)
y_t = torch.tensor(y, dtype=torch.float32).unsqueeze(1)   # (200,) → (200,1)

torch.manual_seed(0)
model = nn.Sequential(nn.Linear(2, 16), nn.ReLU(), nn.Linear(16, 1))
loss_fn   = nn.BCEWithLogitsLoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.5)

for i in range(1, 4001):
    optimizer.zero_grad()        # ① 前回の勾配をリセット
    logits = model(X_t)
    loss = loss_fn(logits, y_t)
    loss.backward()              # ② backprop（自動）
    optimizer.step()             # ③ 勾配降下で1歩

    if i in (1, 100, 500, 2000, 4000):
        acc = ((torch.sigmoid(logits) >= 0.5).float() == y_t).float().mean()
        print(f"更新 {i:5d}回 | Loss: {loss.item():.4f} | 正答率: {acc.item():.1%}")
更新     1回 | Loss: 0.6807 | 正答率: 50.0%
更新   100回 | Loss: 0.2652 | 正答率: 85.5%
更新   500回 | Loss: 0.0449 | 正答率: 99.0%
更新  2000回 | Loss: 0.0057 | 正答率: 100.0%
更新  4000回 | Loss: 0.0024 | 正答率: 100.0%
  • NumPy 版と同じく 100%。zero_grad → backward → step の3拍子はどんなネットでも同じ

3拍子の①は、なぜ要る？

クイズ

optimizer.zero_grad() を消したら、何が起きると思う？

import torch

theta = torch.tensor(2.0, requires_grad=True)
opt = torch.optim.SGD([theta], lr=0.1)

loss = theta ** 2
loss.backward()
print(theta.grad)    # dL/dθ = 2θ = 4
opt.step()
print(theta)         # 2 − 0.1 × 4 = 1.6（step は勾配降下そのもの）

loss = theta ** 2    # zero_grad しないで、もう1周
loss.backward()
print(theta.grad)    # 2θ = 3.2 のはず……が？
tensor(4.)
tensor(1.6000, requires_grad=True)
tensor(7.2000)
  • grad は上書きではなく足し込み（4 + 3.2 = 7.2）— 前回の勾配が残ったまま歩くと方向を誤る
  • だから毎周リセットが①。step() が③（θ -= lr * grad そのもの）

Tweak ネットワークを組み替えて再学習

  • 学習ループのコード を書き換えて実行（境界の図まで続けて実行すると変化が見える）
やりたいこと コード

ここで観察

  • 変換2個：「変換を重ねる」の回では2個でも分けられたのに、ここでは87%止まり（torch.manual_seed(3) だと50%まで転落）。表現力はあっても、良い谷にたどり着けるかは別問題 — 16個の「余裕」は学習の保険でもある（ローカルミニマムの罠）
  • nn.Identity()：折り目ゼロ — 境界が直線に戻り、87%で頭打ち。「線形は重ねても線形」を PyTorch でも再確認
  • どれを変えても、学習ループの3拍子は一切書き換えないで済む — それが部品化の威力

練習問題

以下の問題をPythonコードで解け。

問題1：autograd に自分の手計算を言い当てさせる

バックプロパゲーションの回の練習問題1（\(x = (0.5, 1.0)\)、\(y = 0\)、\(\alpha = (0.4, 0.3)\)、\(b = -0.1\)、\(w = -0.5\)、\(c = 0.2\)）を PyTorch で組み、loss.backward() の勾配が自分の手計算と一致することを確かめよ。

  1. 本編の「山場」のコードを、上の数値に差し替える（正解が \(y = 0\) なので損失は \(L = -\log(1-p)\)）
  2. 5つの勾配を表示し、手計算の答え \((-0.125, -0.25)\)、\(-0.25\)、\(0.2\)、\(0.5\) と照合せよ

問題2：ReLU に折られた入力でも試す

入力を \(x = (-1.0, 0.5)\) に変えて実行し、\(\alpha, b, w\) の勾配がちょうどゼロになることを確かめよ。 （バックプロパゲーションの回の練習問題2 — autograd も、折られた経路には勾配を流さない）

解答例

解答例を見る 
import torch

def hand_check(x1, x2):
    a = torch.tensor([0.4, 0.3], requires_grad=True)   # α1, α2
    b = torch.tensor(-0.1, requires_grad=True)
    w = torch.tensor(-0.5, requires_grad=True)
    c = torch.tensor(0.2,  requires_grad=True)
    x = torch.tensor([x1, x2])

    z = a @ x + b
    h = torch.relu(z)
    u = w * h + c
    p = torch.sigmoid(u)
    L = -torch.log(1 - p)     # 正解 y=0
    L.backward()

    print(f"x = ({x1}, {x2}) | L = {L.item():.4f}")
    print(f"  ∂L/∂α = {a.grad.numpy().round(4)}, ∂L/∂b = {b.grad.item():.4f}, "
          f"∂L/∂w = {w.grad.item():.4f}, ∂L/∂c = {c.grad.item():.4f}")

hand_check(0.5, 1.0)    # 問題1：手計算 (-0.125, -0.25), -0.25, 0.2, 0.5 と一致するはず
hand_check(-1.0, 0.5)   # 問題2：α, b, w の勾配はゼロになるはず
x = (0.5, 1.0) | L = 0.6931
  ∂L/∂α = [-0.125 -0.25 ], ∂L/∂b = -0.2500, ∂L/∂w = 0.2000, ∂L/∂c = 0.5000
x = (-1.0, 0.5) | L = 0.7981
  ∂L/∂α = [-0.  0.], ∂L/∂b = 0.0000, ∂L/∂w = 0.0000, ∂L/∂c = 0.5498
  • 問題1：全桁一致。autograd は連鎖律の機械化であって、魔法ではない
  • 問題2：\(\mathrm{ReLU}'(z) = 0\) の「ゼロで潰す」まで、忠実に再現される
