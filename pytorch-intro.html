質問

層の数や活性化関数を変えるたびに、backward を書き直すことになる。 100層のネットで、1ヶ所も間違えずに書ける？

  • 書けるかもしれないが、人間がやるべき仕事ではない
  • 連鎖律は機械的な作業 — 機械的な作業は機械にやらせる

NumPy版のどこをPyTorchへ任せるのか

NumPy版で自分で書いたもの PyTorchで担当するもの
パラメータ配列と初期化 nn.Linear
forward(...) model(X)
backward(...) loss.backward()
parameter -= lr * gradient optimizer.step()
勾配配列の管理 各パラメータの .grad
  • モデルの計算内容は変わらない
  • 手で書いていた定型処理を、検証済みの部品へ任せる

PyTorchは別の学習原理ではない。NumPyで書いた同じ計算を管理してくれる道具

PyTorch とは

  • ディープラーニングで広く使われるライブラリのひとつ
  • このデッキで使う中心機能は2つ
    • autograd：backward を自動でやってくれる
    • nn：層・損失・最適化の部品セット

requires_grad：勾配を覚える印

  • まずいちばん小さな例で挙動を見る。\(y = x^2\) の \(x = 3\) での微分は、高校の答えなら \(2x = 6\)
import torch

x = torch.tensor(3.0, requires_grad=True)   # 「勾配を追跡せよ」の印
y = x ** 2
y.backward()                                # ← 微分はこの1行
print(x.grad)
tensor(6.)
  • requires_grad=True を付けた tensor は、自分が関わった計算をすべて記録する
  • backward() を呼ぶと、記録を逆にたどって微分が計算され、x.grad に入る
  • \(x^2\) で当たるのは当たり前？ — 次で、前回1往復ぶん手計算したネットワークに同じことをやらせる

forward中に計算グラフが作られる

  • y = ((x * 3) + 1) ** 2 を実行すると、演算のつながりも記録される
  • y.backward() は「2乗 → 足し算 → 掛け算」の逆順に局所微分を適用する
  • Pythonで書いた実際のforwardに応じて、その場でグラフが作られる

ノート

層を組み替えても、PyTorchが新しい計算グラフを記録するため、backwardを手で書き直さなくてよい

autograd を手計算と照合する

  • バックプロパゲーションの回とまったく同じネットワーク・同じ数値を流す
w = torch.tensor([0.3, -0.2], requires_grad=True)   # w1, w2
b = torch.tensor(0.1,  requires_grad=True)
v = torch.tensor(0.5,  requires_grad=True)
c = torch.tensor(-0.1, requires_grad=True)
x = torch.tensor([1.0, 0.5])                        # 入力（正解 y=1）

z = w @ x + b          # 線形変換
h = torch.relu(z)      # ReLU
u = v * h + c          # 出力層
p = torch.sigmoid(u)   # シグモイド
L = -torch.log(p)      # 交差エントロピー（正解1）

L.backward()           # ← 復路はこの1行

print(f"L = {L.item():.4f}")
print(f"∂L/∂w = {w.grad.numpy().round(4)}")
print(f"∂L/∂b = {b.grad.item():.4f}")
print(f"∂L/∂v = {v.grad.item():.4f}")
print(f"∂L/∂c = {c.grad.item():.4f}")
L = 0.6685
∂L/∂w = [-0.2438 -0.1219]
∂L/∂b = -0.2438
∂L/∂v = -0.1463
∂L/∂c = -0.4875

答え合わせ

手計算（とNumPy検算）の答えは \(w\): \((-0.2438, -0.1219)\)、\(b\): \(-0.2438\)、\(v\): \(-0.1463\)、\(c\): \(-0.4875\)。 表示した小数第4位まで一致。 loss.backward() の中身は、前回自分の手でやった連鎖律の機械化。

.grad に入るのは学習したい値

  • w, b, v, c：人が用意したパラメータで requires_grad=True
  • z, h, u, p, L：forward中に作られた途中の値
  • L.backward() 後、学習に使う勾配は w.grad, b.grad, v.grad, c.grad に保存される
種類 例 通常 .grad を残すか
葉（leaf tensor） w, b, v, c 残す
中間結果 z, h, u, p 計算には使うが通常は残さない

計算グラフは全勾配を計算するために使い、optimizerが必要とするパラメータの .grad を残す

なぜ自動でできるのか

  • forward の間、PyTorch は計算の履歴（計算グラフ）を記録している
  • backward() は、その履歴を逆順にたどって連鎖律を適用するだけ
  • やっていることは前回の手計算1往復と同じ：
    • 往路の途中の値を保存（だからメモリを食う）
    • \(\delta\) を出力側から掛けて貯める

ヒント

ブラックボックスとして使うのと、中身を知って使うのは別物。 われわれは中身を手で再現済みなので、堂々と楽をしてよい。

BCEWithLogitsLoss は2部品をまとめる

  • logit（ロジット） \(u\)：シグモイドへ入れる前の、範囲制限のないスコア
  • BCEWithLogitsLoss：シグモイドと2クラス交差エントロピーを1つにした損失関数

\[u \xrightarrow{\;\sigma\;} p \xrightarrow{\;\text{交差エントロピー}\;} L\]

import torch
import torch.nn as nn

logits = torch.tensor([-2.0, 0.0, 2.0])
targets = torch.tensor([0.0, 1.0, 1.0])
loss_each = nn.BCEWithLogitsLoss(reduction="none")

print("確率:", torch.sigmoid(logits))
print("損失:", loss_each(logits, targets))
確率: tensor([0.1192, 0.5000, 0.8808])
損失: tensor([0.1269, 0.6931, 0.1269])
  • モデルは \(u\) をそのまま損失関数へ渡す
  • 確率を表示・判定するときだけ torch.sigmoid(u) を使う

なぜ確率ではなくlogitを直接渡すのか

数式上は、次の2通りは同じ：

u → sigmoid → BCELoss
u ─────────→ BCEWithLogitsLoss
  • \(|u|\) が大きいと、シグモイドの結果は計算機上で0や1へ極端に近づく
  • その後に log(p) や log(1-p) を計算すると、丸め誤差や log(0) が起きやすい
  • BCEWithLogitsLoss は同じ式を、数値的に安定する形へまとめて計算する

重要

学習時は raw logitsを損失へ。確率が必要な表示・判定時だけ torch.sigmoid

optimizer.step() が勾配降下の1歩

import torch

theta = torch.tensor(2.0, requires_grad=True)
optimizer_demo = torch.optim.SGD([theta], lr=0.1)

loss = theta ** 2
loss.backward()
print("勾配:", theta.grad)       # 2θ = 4

optimizer_demo.step()
print("更新後:", theta)          # 2 − 0.1 × 4 = 1.6
勾配: tensor(4.)
更新後: tensor(1.6000, requires_grad=True)

\[\theta \leftarrow \theta-0.1\frac{dL}{d\theta} =2-0.1\times4=1.6\]

  • loss.backward()：勾配を計算して .grad に入れる
  • optimizer.step()：その勾配を使ってパラメータを更新する

optimizerはパラメータへの参照を持つ

optimizer = torch.optim.SGD(model.parameters(), lr=0.5)
  • model.parameters()：更新対象をoptimizerへ渡す
  • lr=0.5：学習率 \(\alpha\)
  • step()：各パラメータについて parameter -= lr * parameter.grad
呼び出し パラメータ .grad
loss.backward() 変えない 計算して足す
optimizer.step() 更新する 読むだけ
optimizer.zero_grad() 変えない 0に戻す

微分・更新・リセットは別の仕事。3つの命令を順番に呼ぶ

学習ループ：3拍子

from sklearn.datasets import make_moons

X, y = make_moons(n_samples=200, noise=0.1, random_state=42)
X_t = torch.tensor(X, dtype=torch.float32)
y_t = torch.tensor(y, dtype=torch.float32).unsqueeze(1)   # (200,) → (200,1)

torch.manual_seed(0)
model = nn.Sequential(nn.Linear(2, 16), nn.ReLU(), nn.Linear(16, 1))
loss_fn   = nn.BCEWithLogitsLoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.5)

for i in range(1, 4001):
    optimizer.zero_grad()        # ① 前回の勾配をリセット
    logits = model(X_t)
    loss = loss_fn(logits, y_t)
    loss.backward()              # ② backprop（自動）
    optimizer.step()             # ③ 勾配降下で1歩

    if i in (1, 100, 500, 2000, 4000):
        with torch.no_grad():
            logits_log = model(X_t)
            loss_log = loss_fn(logits_log, y_t)
            acc = ((torch.sigmoid(logits_log) >= 0.5).float() == y_t).float().mean()
        print(f"更新 {i:5d}回 | Loss: {loss_log.item():.4f} | 正答率: {acc.item():.1%}")
更新     1回 | Loss: 0.6516 | 正答率: 84.5%
更新   100回 | Loss: 0.2647 | 正答率: 85.5%
更新   500回 | Loss: 0.0448 | 正答率: 99.0%
更新  2000回 | Loss: 0.0057 | 正答率: 100.0%
更新  4000回 | Loss: 0.0024 | 正答率: 100.0%

import torch

def hand_check(x1, x2):
    w = torch.tensor([0.4, 0.3], requires_grad=True)   # w1, w2
    b = torch.tensor(-0.1, requires_grad=True)
    v = torch.tensor(-0.5, requires_grad=True)
    c = torch.tensor(0.2,  requires_grad=True)
    x = torch.tensor([x1, x2])

    z = w @ x + b
    h = torch.relu(z)
    u = v * h + c
    p = torch.sigmoid(u)
    L = -torch.log(1 - p)     # 正解 y=0
    L.backward()

    print(f"x = ({x1}, {x2}) | L = {L.item():.4f}")
    print(f"  ∂L/∂w = {w.grad.numpy().round(4)}, ∂L/∂b = {b.grad.item():.4f}, "
          f"∂L/∂v = {v.grad.item():.4f}, ∂L/∂c = {c.grad.item():.4f}")
