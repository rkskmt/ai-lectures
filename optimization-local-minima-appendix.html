谷の数と勾配降下法

谷が1つの関数

  • 勾配降下法（gradient descent）で最小化した \(f(x) = x^2 - 4x + 3\) は2次関数（quadratic function）
    • 谷が1つだけのシンプルな形
    • どこから始めても、同じ最小値 \(x = 2\) にたどり着く

ノート

  • 勾配降下法：傾きを測り、逆方向に少し進む、を繰り返す
  • 学習率（learning rate）が適切なら、谷の底にたどり着く
  • スタート地点を変えても、たどり着く場所は同じ

谷が2つ以上ある関数

今回の主題

谷が2つ以上ある関数では、勾配降下法はどうなるのか

  • 機械学習（machine learning）でも、線形回帰やロジスティック回帰の損失は谷が1つ
  • ニューラルネットワーク（neural network）のようにパラメータが多いモデルでは、たくさんの谷が存在する
  • 谷が2つある関数で、勾配降下法の動きを確かめる

谷が2つある関数

関数の定義

今回使う関数：

\[f(x) = 0.1x^4 - x^3 + 2x^2 + 1\]

微分を手で計算しておく。

1次微分（first derivative、傾き）: \[f'(x) = 0.4x^3 - 3x^2 + 4x\]

2次微分（second derivative、曲がり具合）: \[f''(x) = 1.2x^2 - 6x + 4\]

Pythonでの定義

    return 0.4*x**3 - 3*x**2 + 4*x

def f_poly_double_prime(x):
    return 1.2*x**2 - 6*x + 4

初期値を変えて実行する

スタート地点だけを変える

  • 勾配降下法の更新式をそのまま使う：

\[x_{\text{new}} = x - \alpha \cdot f'(x)\]

  • 学習率は \(\alpha = 0.1\) に固定する
  • スタート地点（初期値、initial value）だけを変えて2回実験する
def gradient_descent(f, fp, x0, lr=0.1, tol=1e-6, max_iter=10000):
    """勾配降下法：収束した場所・そこでの f(x)・通り道を返す"""
    x = x0
    history = [x]
    for i in range(max_iter):
        grad = fp(x)
        if abs(grad) < tol:      # 傾きほぼゼロ → 収束
            break
        x = x - lr * grad     # Move a little against the gradient
        history.append(x)
    return x, f(x), history

2つの実験を並べる

たどり着いた谷が違う

同じ勾配降下法でも、初期値が違うとたどり着く谷が変わる

スタート地点 到着地点
実験1 \(x_0 = 0.5\) 谷（左）
実験2 \(x_0 = 5.5\) 谷（右・もっと深い）
  • どちらも谷（\(f''>0\)）だが、深さがまったく違う
  • 実験1の答えは、その周辺では最適でも全体では最適ではない
    • 実行した結果だけを見ても、もっと深い谷があることには気づけない

谷の種類

ローカルミニマムとグローバルミニマム

  • ローカルミニマム（局所的最小値, local minimum）：その周辺では一番低いが、関数全体で見るともっと低い場所がある点
    • 実験1で到達した左の谷（\(x = 0\)）
  • グローバルミニマム（大域的最小値, global minimum）：関数全体で一番低い点
    • 実験2で到達した右の谷

たとえ話：山の中で一番低い場所を探す

目隠しをして山の中に立ち、足元の傾きだけを頼りに一番低い場所を探す

  • 近くの谷には降りられる → ローカルミニマム
  • 山の向こうに、もっと深い谷があるかもしれない → グローバルミニマム
  • 目隠しをしているので、今いる谷が一番深いかどうかはわからない

勾配降下法も Newton法（Newton’s method）も、この「目隠し」と同じ状況にある

初期値と引力圏

勾配降下法は「目の前の坂」しか見ない

  • 勾配降下法は、いまいる場所の傾きだけを見て一歩を決める
    • 遠くにもっと深い谷があっても、目の前の坂を下ることしかできない
  • 左の谷の近くからスタート → 左の谷（ローカルミニマム）に落ちる（実験1）
  • 右の谷の近くからスタート → 右の谷（グローバルミニマム）に落ちる（実験2）

図の見方（下のグラフ）

  • 横軸：スタート地点 x0
  • 縦軸：そこから勾配降下法が最終的にたどり着いた場所
  • 縦に1本選んで読む：「x0 = 1 から出発 → 点の高さは 0 → 左の谷に着いた」
  • 点は2つの高さのどちらかに集まる
    • 行き先は左の谷（赤）か右の谷（緑）の2択
  • 背景の色の帯から出発すると、同じ色の谷に吸い込まれる
    • 上下のグラフは横軸が揃えてある

引力圏（Basin of Attraction）

  • 引力圏：その範囲からスタートすると、その谷に吸い込まれる領域
  • 勾配降下法の引力圏は、丘のてっぺんを境に2つに分かれる
    • てっぺんより左なら左の谷、右なら右の谷
  • 答えはスタート地点を選んだ時点で決まる
  • どちらの谷が深いかは、降りてみるまでわからない
    • だから1回の実行の結果を信用してはいけない

引力圏を立体で見る

  • パラメータが2個になると、地形は面になる
  • 谷が2つある地形 \(f(w_1, w_2) = (w_1^2 - 1)^2 + 0.5\, w_2^2\)（谷底は \(w_1 = \pm 1\)）で、少しだけ違う2地点からスタートする

チェックポイント

  • スタートの差は \(w_1\) が \(+0.1\) か \(-0.1\) かだけ
    • それでも赤は右の谷、橙は左の谷に吸い込まれる
  • ドラッグで回して、2つの谷の間の尾根を確認
    • 尾根が引力圏の境界線
  • 実際の機械学習の地形は、こうした谷が多数ある高次元版
    • だから初期値しだいで別の答えに落ち着く

グローバルミニマムの探し方

対策：初期値を変えて何回も試す

  • 勾配降下法は正しく動いている
    • ただし、どの谷に着くかはスタート地点で決まる
  • どちらの谷が深いかは、降りてみるまでわからない（目隠しの限界）

重要ポイント

スタート地点を変えて何回も実行し、一番良い結果を選ぶ

方法1：手で初期値を変えて比較する

  • まず3つの初期値から実行して比較する
  • \(x_0 = 0\) からスタート
  • \(x_0 = 2\) からスタート
  • \(x_0 = 6\) からスタート

\[f'(0) = 0.4 \times 0 - 3 \times 0 + 4 \times 0 = 0\]

  • 傾きがゼロなので、勾配降下法は一歩も動かない
    • \(x = 0\)、\(f(0) = 1\) ですぐに「収束」する
  • \(f''(0) = 4 > 0\) なので、ここは谷
    • ただし谷底から始めると、隣にもっと深い谷があっても気づけない

\[f'(2) = 0.4 \times 8 - 3 \times 4 + 4 \times 2 = 3.2 - 12 + 8 = -0.8\]

傾きがマイナス（右下り坂）→ 一歩は右へ：

\[x_{\text{new}} = 2 - 0.1 \times (-0.8) = 2.08\]

そのまま坂を下り続けて、右の谷（グローバルミニマム）に着く

\[f'(6) = 0.4 \times 216 - 3 \times 36 + 4 \times 6 = 86.4 - 108 + 24 = 2.4\]

傾きがプラス（右上り坂）→ 一歩は左へ：

\[x_{\text{new}} = 6 - 0.1 \times 2.4 = 5.76\]

こちらも右の谷に着く

ランダムリスタート vs グリッドサーチ

方法 やり方 長所 短所
ランダムリスタート 初期値をランダムに選ぶ 簡単、偏りが少ない 運に左右される
グリッドサーチ 初期値を等間隔に並べる 漏れが少ない 数が多いと大変

どちらも「何回も試して一番良いものを選ぶ」という考え方

k-means のランダムリスタート

kmeans_best(xs, ys, k, n_init=10) はランダムリスタート

  • k-means も、クラスタ中心の初期値しだいで変な分け方に落ち着く
  • kmeans_best(xs, ys, k, n_init=10) は、初期値を変えて10回実行し、SSE が最小の結果を採用する
  • 「初期値を変えて何回も試し、一番良いものを選ぶ」という考え方は、初期値の用意のしかた（手動・ランダム・グリッド）によらず同じ
    • 最適化（optimization）の分野ではまとめて multi-start と呼ぶこともある
  • ニューラルネットワーク（neural network）で「乱数シードを変えて学習し直す」のもランダムリスタート
  • 名前は違っても、やっていることは方法1〜3と同じ

最適化の手順

最適化の4ステップ

  • 最適化問題は、次の手順で解く

ステップ1：関数を可視化する

  • グラフを描いて、谷がいくつあるかを確認する
  • 谷が複数ありそうなら、ローカルミニマムに注意する

ステップ2：複数の初期値を用意する

  • 最低でも3〜5個、余裕があれば10個以上
  • グリッドサーチかランダムリスタートで用意する

ステップ3：全部実行して、結果を比較する

  • すべての初期値から最適化（勾配降下法など、手法は問わない）を実行する
  • \(f(x)\) が一番小さい結果を選ぶ

ステップ4：2次微分で確認する

  • 収束した点で \(f''(x) > 0\) なら谷（ローカルミニマム）
  • \(f''(x) < 0\) なら山なので捨てる
  • 勾配降下法が山で止まることはほとんどないが、確認は1行で済むので保険として常に入れておく
    • Newton法では必須

def robust_optimization(f, fp, fpp, x0_list, lr=0.1, max_iter=10000):
    """
    複数の初期値を使ったロバストな最適化（勾配降下法版）

    Parameters:
    -----------
    f, fp, fpp : functions
        目的関数とその1次微分、2次微分（2次微分は谷の検品用）
    x0_list : list
        初期値のリスト
    lr : float
        学習率
    max_iter : int
        最大反復数

    Returns:
    --------
    best_x : float
        見つかった最良解
    all_results : list
        比較用のすべての結果
    """
    all_results = []

    for x0 in x0_list:
        x = x0

        for i in range(max_iter):
            grad = fp(x)
            if abs(grad) < 1e-6:       # 傾きほぼゼロ → 収束
                break
            x = x - lr * grad       # Move a little against the gradient

        all_results.append({
            "x0": x0,
            "x_final": x,
            "f_final": f(x),
            "is_minimum": fpp(x) > 0   # ステップ4：谷の検品
        })

    # 谷（ローカルミニマム）だけを残して、一番良いのを選ぶ
    minima = [r for r in all_results if r["is_minimum"]]
    if minima:
        best_result = min(minima, key=lambda r: r["f_final"])
    else:
        best_result = min(all_results, key=lambda r: r["f_final"])

    return best_result["x_final"], all_results

                                          initial_values)

def newton_naive(f, fp, fpp, x0, tol=1e-6, max_iter=100):
    """素のNewton法：収束点と反復回数を返す"""
    x = x0
    for i in range(max_iter):
        g = fp(x)
        if abs(g) < tol:
            return x, f(x), i
        x = x - g / fpp(x)
    return x, f(x), max_iter

質問

それなら、いつも Newton法を使えばよいのか？

実験3：丘の中腹 \(x_0 = 1.5\) から始める

  • 同じ更新式で計算すると：\(1.5 \rightarrow 1.761 \rightarrow 1.735 \rightarrow\) 停止（\(f' \approx 0\)）
  • 左に下り坂があるのに、坂を登って丘のてっぺんで止まった

坂を登る理由

  • 一歩の向きは \(-f'/f''\)
    • \(f'(1.5) = +0.6\)（右上り坂）、\(f''(1.5) = -2.3\)（上に凸、concave）
  • 符号が打ち消し合って、一歩は \(+0.26\)
    • 傾きと同じ向き、つまり登る向きになる
  • Newton法が探しているのは「\(f' = 0\) の点」だけ
    • そこが山か谷かは見ていない
  • 停止条件（\(|f'|\) がほぼゼロ）は山頂でも満たされる
    • 山で止まる

\(f''\) チェックは「止まった後の検品」

  • 収束したら \(f''(x)\) を確認する：正なら谷、負なら山
    • 山なら結果を捨てる
  • 山か谷かを区別できるのは、止まった後
    • 実行中の Newton法には、登りを避けるブレーキがない
  • ブレーキは後から組み込める

Newton法は「近くの傾きゼロ」に落ちる

  • Newton法が探しているのは「傾きゼロの点」
    • そこが谷か山頂かは見ていない
  • 谷の近くから → その谷に落ちる（実験1・2と同じ初期値での結果）
  • 丘の上から → 山頂に登って止まる（実験3）
  • 勾配降下法のときと同じように、初期値200個で引力圏の地図を描く

Newton法の引力圏

  • 勾配降下法の引力圏は、丘のてっぺんを境に2つに分かれた
  • Newton法ではどうなるか

def newton_optimize(f, fp, fpp, x0, max_iter=50):
    """Newton法を実行して結果を返す"""
    x = x0
    for i in range(max_iter):
        grad = fp(x)
        hess = fpp(x)
        if abs(grad) < 1e-6:
            return x, f(x), True
        if abs(hess) < 1e-10:
            return x, f(x), False
        x = x - grad / hess
    return x, f(x), False

結果

  • 赤い帯 → ローカルミニマム
  • 緑の帯 → グローバルミニマム
  • 橙の帯 → 山のてっぺん（極大、local maximum）に到着して止まる
    • Newton法が探しているのは「傾きゼロの場所」なので、谷と山頂を区別できない
  • 帯の並びは、丘のてっぺんを境にした2分割にならない
    • グローバルミニマムのすぐ手前から出発しても、左の谷へ飛ばされる
  • 初期値が少し変わるだけで、行き先が大きく変わる
    • 1回の実行の結果を信用してはいけない

なぜ「すぐ手前の帯」が左へ飛ぶのか

  • x0 = 4.0 から始めたときの最初の1歩を詳しく見る

結果

  • Newton法の1歩は「いまの場所に放物線を当てはめて、その頂点へジャンプする」（\(x - f'/f''\) の意味）
  • x0=4 は、2つの変曲点（inflection point）x≈0.79 と x≈4.21 の間にある上に凸の区間の右端
    • 当てはめた放物線が逆さまになり、頂点は左の遠く（x=−4）にある
  • 変曲点の近くでは \(f'' \approx 0\) なので、割り算 \(f'/f''\) の値が非常に大きくなり、飛距離が伸びる
  • 着地した x=−4 は左の谷の下に凸（convex）の区間
    • あとは x=0 に収束する
  • 細い緑の帯は同じ現象の逆向き
    • 左の変曲点のすぐ内側から右へ大きくジャンプして、右の谷に着く

重要

  • 大きくジャンプできるのが Newton法の強み
    • 放物線の近似が外れる場所では、同じジャンプが失敗の原因になる
  • 勾配降下法は「傾きの逆に少しずつ」進むので、x0=4 からは右の谷へ降りる

Newton法の修理

2種類の失敗の原因

  • 山頂で止まる（実験3）
    • 上に凸の場所では、一歩が登る向きになる
  • 反対側へ大きく飛ぶ（x0=4 の例）
    • 変曲点の近くでは、一歩が大きすぎる
  • 原因はどちらも、当てはめた放物線の頂点へ検査なしでジャンプすること

修理方針

提案された一歩を、2つの検査に通してから踏む

検査1：その方向は「下り」か

  • Newton法の一歩 \(d = -f'/f''\) は提案として扱う
  • 踏む前に確認する：\(f' \cdot d \geq 0\) なら、提案は傾きと同じ向き＝登りなので却下
  • 却下したら、確実に下る最急降下方向（steepest descent direction） \(d = -f'\) に差し替える
  • 登りの提案が出るのは、\(f'' < 0\)（上に凸）の場所
    • 実験3とx0=4 の例は、どちらもこの場所

実験3の \(x = 1.5\) で確かめる：

  • 提案は \(d = +0.26\)
  • \(f' \cdot d = 0.6 \times 0.26 > 0\) → 登りなので却下 → \(d = -f' = -0.6\)（左の下りへ）

検査2：実際に \(f\) が下がるか

  • 向きが正しくても、歩幅が大きすぎると谷を飛び越えて高い場所に着くことがある
  • 踏む前に、着地点の \(f\) の値を実際に計算する：
    • 十分下がっていれば採用
    • 下がっていなければ歩幅を半分にしてやり直す（バックトラッキング、backtracking）
  • 放物線の予測ではなく、実際の \(f\) の値を確かめてから進む

修理版Newton法（検査1・2入り）

def newton_safe(f, fp, fpp, x0, max_iter=100):
    """Newton法＋検査1（降下方向）＋検査2（実測バックトラッキング）"""
    x = x0
    for _ in range(max_iter):
        g = fp(x)
        if abs(g) < 1e-8:                  # 傾きほぼゼロ → 停止
            break
        h = fpp(x)
        d = -g / h if h != 0 else -g       # Newton法の「提案」
        if g * d >= 0:                     # 検査1：登りなら却下して
            d = -g                         #   最急降下に差し替え
        step_size = 1.0
        while f(x + step_size * d) > f(x) - 1e-4 * step_size * abs(g * d):
            step_size /= 2                 # Halve the step until the value decreases
        x = x + step_size * d
    return x, f(x)

# 失敗していた2つの初期値で確認
for x0 in [1.5, 4.0]:
    x_fin, f_fin = newton_safe(f_poly, f_poly_prime, f_poly_double_prime, x0)
    print(f"x0 = {x0} → x = {x_fin:.4f}, f(x) = {f_fin:.4f}")

x0 = 4.0 → x = 5.7656, f(x) = -13.6726

  • 反対側へ飛んでいた \(x_0 = 4\) は右の谷（グローバルミニマム）へ降りた

結果

  • 山頂の帯（橙）も、飛ばされる帯も消えた
    • てっぺんより左なら左の谷、右なら右の谷
  • 検査1・2で直せるのは、この2種類の失敗まで

ライブラリには検査が組み込まれている

  • scipy などの実用ソルバーは、この種の検査を毎回の更新に組み込んでいる：
    • BFGS：常に下り向きの提案が出るように作った近似 \(f''\) を使う
    • Newton-CG：負の曲率（negative curvature、上に凸）を検出すると計算を打ち切り、勾配方向へ切り替える
    • 信頼領域法（trust region method）：放物線を「信じる半径」の中でだけ使う
  • 実測：\(x_0 = 1.5\) から scipy.optimize.minimize を呼ぶと、BFGS / Newton-CG / trust-exact のすべてが山頂に登らず \(x=0\) の谷に降りる
  • 方法は違っても、考え方は同じ：\(f\) が下がらない一歩は踏まない

ノート

  • 教科書の Newton法は、もともと「\(f'=0\) を解く」方法
    • 最小化に使うための検査は含まれていない
  • ライブラリには、その検査が組み込まれている

Newton法のまとめ：検査で直るのは2種類の失敗だけ

  • 山頂で止まる・反対側へ飛ぶ失敗は、検査1・2で直せる
    • ライブラリにはこの検査が組み込まれている
  • 修理後も、行き先は2つある
    • どの谷に落ちるかは初期値しだいのまま
  • これは Newton法の欠陥ではなく、目隠しで坂を下ること自体の限界（目の前の谷しか見えない）
  • だから、複数の初期値から試す方法（方法1〜3）はどの手法でも必須

まとめ

まとめ

ノート

  1. 谷が複数ある関数では、答えが初期値に依存する
    • 勾配降下法は目の前の坂を下ることしかできず、近くの谷に落ちる
    • どの初期値がどの谷に行くかの地図が引力圏（境界は丘のてっぺん）
  2. ローカルミニマムとグローバルミニマム
    • ローカルミニマム：周辺では一番低いが、全体では最低ではない
    • グローバルミニマム：全体で一番低い点
  3. 対策は「複数の初期値から試して、一番良い結果を選ぶ」
    • ランダムリスタートやグリッドサーチで初期値を用意する
    • k-means の kmeans_best(xs, ys, k, n_init=10) も同じ方法
    • 2次微分の確認（\(f'' > 0\) なら谷）は保険として常に入れる
  4. Newton法は速いが、山頂で止まる・反対側へ飛ぶという失敗も起こす
    • 検査1（下り向きか）・検査2（実際に下がったか）で直せる
      • ライブラリにはこの検査が組み込まれている
    • それでも「どの谷か」は初期値で決まるので、初期値を変えて試すしかない

ニューラルネットワークの場合

  • ニューラルネットワークの損失関数は、パラメータが何万個もある谷だらけの地形
  • 同じデータで学習し直すたびに結果が少し違うのは、初期値（乱数）しだいで別の谷に落ちるから
  • 「何回か学習して一番良いものを選ぶ」方法は、深層学習でも使われている
