画像は784次元のベクトル

  • 28 × 28 = 784個の数字の並び — モデルにとって画像は784次元のベクトル
  • 魚は2次元（輝度・重さ）だった。次元の呪いの回で扱った高次元が、本物の入力として現れる
  • nn.Flatten() が「画像 → ベクトル」の変換をやる
import torch
import torch.nn as nn

sample = torch.zeros(1, 1, 28, 28)  # 1枚ぶんのダミー画像
flat = nn.Flatten()(sample)
print("変換前:", tuple(sample.shape))
print("変換後:", tuple(flat.shape))
変換前: (1, 1, 28, 28)
変換後: (1, 784)

ノート

784次元でも、やることは魚の2次元と完全に同じ： 特徴量ベクトル → 変換を重ねる → 確率 → 損失 → 勾配降下。

1画素は0〜1の数値になる

transforms.ToTensor() は、元画像の0〜255を0〜1へ変換する：

\[x_{\rm tensor}=\frac{x_{\rm pixel}}{255}\]

元の画素値 tensorの値 この画像での意味
0 0.0 背景
128 約0.50 中間の濃さ
255 1.0 強い筆跡
  • 784個の特徴量は、各場所にどれくらい筆跡があるかを表す
  • 入力の尺度をそろえると、勾配降下法が扱いやすい

ノート

画像として見えていても、モデルへ入る時点では0〜1の数値784個

出力層を付け替える：10クラス分類

  • 答えは Salmon / Sea bass の2択ではなく、0〜9 の10択
  • 「変換を重ねる」の回の表のとおり、出力層を付け替えるだけ
問題 出力の活性化関数
2クラス分類 シグモイド（1個の確率）
多クラス分類 ソフトマックス（10個の確率分布）

\[\mathrm{softmax}(u_k) = \frac{e^{u_k}}{\sum_{j} e^{u_j}} \qquad \text{10個の出力を「合計1の確率」に変換}\]

  • 損失は多クラス版の交差エントロピー：正解クラスの確率 \(p_{\text{正解}}\) に対して \(-\log p_{\text{正解}}\)（あの −log のカーブの10クラス版）
  • PyTorch では nn.CrossEntropyLoss がソフトマックスごとやってくれる（打ち消しの恩恵もそのまま）

スコアを実際にソフトマックスへ入れる

  • 3クラスのスコアを \(u=(2.0,\,1.0,\,0.1)\) とする：

\[e^u=(e^2,e^1,e^{0.1})\approx(7.389,\,2.718,\,1.105)\]

  • 分母は3つの合計：

\[7.389+2.718+1.105=11.213\]

  • それぞれを合計で割る：

\[\mathrm{softmax}(u) \approx\left(\frac{7.389}{11.213}, \frac{2.718}{11.213}, \frac{1.105}{11.213}\right) \approx(0.66,\,0.24,\,0.10)\]

指数関数で全スコアを正にし、合計で割って「合計1の確率分布」にする

ソフトマックスの仕事ぶり

  • スコアが大きいほど確率も大きい。ただし \(e^u\) を通すので差が強調される（スコア差 1.0 が、確率では 0.66 対 0.24）
  • 合計 1 の「自信の配分」になる — 10クラスなら10個のスコアを10個の確率に

CrossEntropyLoss はsoftmax込み

import torch
import torch.nn as nn

logits = torch.tensor([[2.0, 1.0, 0.1]])  # 1件・3クラスのスコア
target = torch.tensor([0])                 # 正解はクラス0
loss_fn_demo = nn.CrossEntropyLoss()

print("確率:", torch.softmax(logits, dim=1))
print("損失:", loss_fn_demo(logits, target))
確率: tensor([[0.6590, 0.2424, 0.0986]])
損失: tensor(0.4170)
  • モデルはsoftmax前のスコア logits をそのまま渡す
  • CrossEntropyLoss の中でsoftmaxと \(-\log p_{\text{正解}}\) が計算される
  • 予測ラベルは、最大スコアの位置 logits.argmax(dim=1) で求められる

モデル：784 → 128 → 10

torch.manual_seed(0)

model = nn.Sequential(
    nn.Flatten(),          # (28,28) → 784
    nn.Linear(784, 128),   # 線形変換
    nn.ReLU(),             # 折る
    nn.Linear(128, 10),    # 出力層（10クラスぶんのスコア）
)

n_params = sum(p.numel() for p in model.parameters())
print(f"パラメータ総数: {n_params:,}")
パラメータ総数: 101,770

  • 魚のロジスティック回帰はパラメータ3個だった。いまや10万個 — それでも学習ループは同じ3拍子

\[\underbrace{784\times128+128}_{\text{第1層}} +\underbrace{128\times10+10}_{\text{出力層}} =101{,}770\]

Adam — 最適化回の伏線回収

  • Adam は、勾配の履歴を使ってパラメータごとに歩幅を調整する最適化手法
  • zero_grad → backward → step の形は、SGD と同じ

128枚がモデルを通るときの形

入力画像          (128, 1, 28, 28)
   ↓ Flatten
784次元ベクトル   (128, 784)
   ↓ Linear + ReLU
中間表現          (128, 128)
   ↓ Linear
10クラスのlogits  (128, 10)
  • 先頭の 128 は、どの段でもミニバッチ内の画像枚数
  • 最後の 10 は数字0〜9それぞれのスコア
  • 正解ラベル y_batch の形は (128,)。各画像につき整数が1個

モデルは1枚ずつの式を、128枚ぶん並行して計算する

ミニバッチ：6万枚は一口ずつ

  • 6万枚まとめて勾配を計算すると重い → 128枚ずつ取り出して1歩ずつ進む — この一口がミニバッチ（mini-batch）

  • NumPyで2層NNを学習した回では、全200件を1つのバッチにして1回更新した
  • 今回は6万枚を128枚ずつのミニバッチへ分け、1ミニバッチごとに1回更新する

1エポックで約469回更新する

訓練画像60,000枚を128枚ずつに分けると：

\[\left\lceil\frac{60{,}000}{128}\right\rceil=469\ \text{ミニバッチ}\]

  • 最初の468バッチは128枚、最後の1バッチは96枚
  • 1ミニバッチごとに zero_grad → backward → step を1回実行する
  • したがって3エポックでは、約 \(469\times3=1{,}407\) 回更新する
  • shuffle=True により、各エポックで画像の順番を入れ替える

ノート

「3エポック」は3回しか更新しないという意味ではない。全データを3周し、その途中で約1,407歩進む

学習する

for epoch in range(1, 4):
    loss_sum = 0.0
    for x_batch, y_batch in train_loader:
        optimizer.zero_grad()
        loss = loss_fn(model(x_batch), y_batch)
        loss.backward()
        optimizer.step()
        loss_sum += loss.item() * len(x_batch)

    # テストデータ（見ていない1万枚）で採点 — 過学習と汎化の回の鉄則
    correct = 0
    with torch.no_grad():
        for x_batch, y_batch in test_loader:
            correct += (model(x_batch).argmax(dim=1) == y_batch).sum().item()
    train_loss = loss_sum / len(train_ds)
    print(f"エポック {epoch} | 訓練Loss: {train_loss:.4f} "
          f"| テスト正答率: {correct / len(test_ds):.2%}")
エポック 1 | 訓練Loss: 0.4125 | テスト正答率: 93.49%
エポック 2 | 訓練Loss: 0.1968 | テスト正答率: 95.15%
エポック 3 | 訓練Loss: 0.1430 | テスト正答率: 96.26%

どの数字とどの数字が混ざるのか

質問

0〜9 のうち、この機械がいちばん混同しやすいペアはどれだと思う？

  • 過学習と汎化の回の混同行列は2×2だった。これはその10クラス版
  • 最多は 4→9（22枚）、逆向きの 9→4 も14枚 — 4と9はお互いに紛らわしい。次点は 7→9・5→3
  • 間違いはランダムに散らばらない。形の似たペアに集中する

自信満々の間違い

  • 最上位は「9」を 99.5%の自信で「4」と誤読 — 精度96%の機械は、間違えるときも自信満々のことがある
  • −log のカーブの左端そのもの。学習中ならこの1枚が莫大な損失を出して重みを大きく動かす
  • 確率はあくまでモデルの主観。「自信がある＝正しい」ではない

育った重みを覗く

  • 第1層 nn.Linear(784, 128) の各ユニットは、784本の重みを持つ ＝ 28×28の「模様」として絵にできる
  • 赤い場所にインクが乗ると足し、青い場所なら引く — その合計が ReLU の入り口 \(z\)
  • 学習前（同じシードで初期化し直したもの）は一様な砂嵐。学習後は中央にインクの通り道の模様が育っている
  • 魚のとき学習された \(w\) を読んだのと同じことを、10万パラメータでやっただけ

自分の字は読めるのか（持ち帰りデモ）

紙に数字を書いて撮影し、この機械に読ませてみよう。 ただし写真をそのまま28×28に縮めても、まず読めない — MNISTの画像は「数字を20ピクセル角に収め、重心をど真ん中に置く」ように揃えてあり、撮った写真はそうなっていないから。同じ揃え方を自分でやってから見せる：

from PIL import Image
import numpy as np
import torch

# 1. 読み込み：グレースケール化して「インク=1、紙=0」に正規化
a = np.array(Image.open("my_digit.png").convert("L"), dtype=np.float32)
a = (a.max() - a) / (a.max() - a.min())

# 2. MNISTと同じ揃え方：数字を切り出し → 長辺20pxに縮小 → 重心を中央へ
rows, cols = np.where(a > 0.3)
a = a[rows.min():rows.max()+1, cols.min():cols.max()+1]
h, w = a.shape
s = 20.0 / max(h, w)
img = Image.fromarray((a * 255).astype(np.uint8)).resize((round(w*s), round(h*s)))
a = np.array(img, dtype=np.float32) / 255.0
x28 = np.zeros((28, 28), dtype=np.float32)
h, w = a.shape
x28[(28-h)//2:(28-h)//2+h, (28-w)//2:(28-w)//2+w] = a
ys, xs = np.mgrid[0:28, 0:28]
cy, cx = (x28*ys).sum()/x28.sum(), (x28*xs).sum()/x28.sum()
x28 = np.roll(x28, (round(14-cy), round(14-cx)), axis=(0, 1))

# 3. 推論
x = torch.tensor(x28).unsqueeze(0).unsqueeze(0)
print("予測:", model(x).argmax(dim=1).item())

うまく読めないとき

ヒント

  • 太いペンで、大きく書く（MNISTの字は線が太い）。紙は白く、明るい場所で撮る
  • それでも読めない字は「間違いを眺める」の仲間入り — 訓練データの字と自分の字の分布の違いが原因
  • 精度96%とは「100枚中4枚は間違える」という意味でもある。1枚読ませて外れても、それはこの機械の正直な実力

到達チェック 96%の中身を読む

「テスト正答率96.3%」だけでは分からないこのモデルの性質を、前の観察から3つ挙げよ。

  1. 混ざりやすい数字の組
  2. 自信満々で間違う例
  3. 自分の手書き画像で成績が変わる理由

この先の世界

  • 画像がもっと大きく複雑になったら？
    • 784次元を全部つなぐのは無駄が多い → 近くのピクセルだけ見る畳み込み（CNN）
  • 入力が文章だったら？
    • 単語同士の関係に重みをつける Attention → Transformer → いまの大規模言語モデル（LLM）
  • どちらも今日の機械と同じ原理の上に立つ：変換を重ねて、損失を決めて、勾配で学習する

ヒント

名前は新しくても、開け方はもう知っている。 「forward は何か」「損失は何か」「勾配はどう流れるか」— この3つを聞けばいい。

講義全体のまとめ

  • 魚の選別から始まり、fit() という1行の中身を開け続けた
    • しきい値 → 直線 → 木 → ロジスティック回帰 → 多層NN
    • 損失（交差エントロピー・MSE）と勾配降下法が全編を貫く背骨
  • 満点を疑うこと（過学習）、スケールを揃えること、テストで採点すること
  • 最後に、手書き数字を読む機械を自分の部品で組み上げた
