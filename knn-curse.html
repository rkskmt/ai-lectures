k-NN と次元の呪い

近いデータのラベルで分類する

rkskmt

ここまでの道具

  • 決定木：データから決定境界を学習し、境界のどちら側かで分類した
  • 距離：k-means で、2点がどれだけ近いかを測った

今回の主題

  • 境界を学習せずに、分類できるか
  • 境界を作らない分類は、特徴量を増やすとどうなるか

似た事例から判断する

  • 新しいものを、似ている過去の例から判断することは多い
    • 例：迷惑メールに似た文面のメールは、迷惑メールだと考える
    • 例：中古車の値段を、年式や走行距離が近い車の値段から見積もる
  • 規則や境界を作らなくても、「似ているデータは、同じラベルを持ちやすい」と考えれば予測できる
  • データどうしが似ているかは、特徴量の空間での距離の近さで測る

  • ラベルは、座標の合計が 1 より大きければ 1、そうでなければ 0

境界で決めるか、近い点の投票で決めるか

要するに

  • 決定木：先に訓練データから境界を作り、★ がどちらの領域に入るかでラベルを決める
  • 近い点の投票：境界は作らず、★ に近い 3 点のラベルを見て、多いほうに決める
    • 近い 3 点のうち 1 点はラベル 0 だが、多数決なので 1 になる

近い k 点の多数決にする（k-NN）

  • 新しい点 \(x\) のラベルを、次の手順で決める
    1. \(x\) から、訓練データの全部の点までの距離を測る
    2. 距離が小さい順に、k 点を選ぶ
    3. k 点のラベルのうち、多いほうを \(x\) のラベルとする
  • k-NN（k-nearest neighbors / k 近傍法）と呼ぶ
    • k は奇数にする（偶数だと、同数で決まらないことがある）
def predict_knn(X_train, y_train, x, k):
    dist    = np.sqrt(((X_train - x) ** 2).sum(axis=1))  # 1. x から、訓練データの全部の点までの距離
    nearest = np.argsort(dist)[:k]                       # 2. 距離が小さい順に並べた番号の、先頭 k 個
    votes   = y_train[nearest]                           #    k 点のラベル（0 か 1）
    return int(votes.sum() > k / 2)                      # 3. ラベル 1 が半分より多ければ 1、そうでなければ 0

x_new = np.array([0.7, 0.6])                             # 前のスライドの ★
print(f"★ の予測（k = 3）: {predict_knn(X_train, y_train, x_new, 3)}")

def accuracy_knn(X_train, y_train, X, y, k):

質問

特徴量（次元）を増やし続けると何が起きるか？

次元の呪い

同じ作り方で、特徴量を増やす

  • データを作る関数 make_data を用意する
    • \(d\) 個の特徴量を持つ点を、0〜1 の範囲にばらまく
    • ラベルは、座標の合計が真ん中の値 \(d / 2\) より大きければ 1（1 割ほどは逆）
    • 2 次元のデータも、この作り方で作った
  • 特徴量を 2, 3, 5, 10, 20 個に増やし、k = 3 の k-NN でテストデータ 1,000 点を予測する
    • 訓練データは、どの次元でも 100 点
rng = np.random.default_rng()                        # 乱数の生成器（実行するたびに違う点になる）

def make_data(n, d):
    X = rng.random((n, d))                           # n 点を、d 次元の 0〜1 の範囲にばらまく
    y = (X.sum(axis=1) > d / 2).astype(int)          # 座標の合計が d/2 より大きければ 1
    flip = rng.random(n) < 0.1                       # 1 割ほどの点を選び、
    y[flip] = 1 - y[flip]                            # ラベルを逆にする
    return X, y

for d in [2, 3, 5, 10, 20]:
    Xd_train, yd_train = make_data(100, d)           # 訓練データ 100 点
    Xd_test,  yd_test  = make_data(1000, d)          # テストデータ 1,000 点
    acc = accuracy_knn(Xd_train, yd_train, Xd_test, yd_test, 3)
    print(f"{d:2d}次元: Accuracy {acc:.3f}")

次元の呪い（Curse of Dimensionality）

  • データの次元が増えるにつれて、空間が指数的に広くなり、データがまばらになる現象
  • 2次元で十分だったサンプル数が、10次元では全く足りなくなる
  • 高次元空間は私たちの直感とは全く異なる振る舞いをする

ノート

名づけたのは Richard Bellman（動的計画法の発明者）。 現代機械学習でも最重要トピックの一つ。

いちばん近い点までの距離を測る

  • 訓練データの点 0 から、ほかの 99 点までの距離をすべて測る
  • その中でいちばん小さいものが、いちばん近い点（最近傍, nearest neighbor）までの距離
  • 100 点それぞれで測り、その中央値を、点の混み具合として使う
def nearest_distance(P, i):
    dist = np.sqrt(((P - P[i]) ** 2).sum(axis=1))    # 点 i から全部の点までの距離
    dist[i] = np.inf                                 # 自分自身は除外
    return dist.min()                                # いちばん近い点までの距離

print(f"点 0 からいちばん近い点まで: {nearest_distance(X_train, 0):.3f}")

nn = []
for i in range(len(X_train)):                        # 100 点すべてで測る
    nn.append(nearest_distance(X_train, i))
print(f"100 点の中央値: {np.median(nn):.3f}")
点 0 からいちばん近い点まで: 0.078
100 点の中央値: 0.052

結果

  • 点 0 からいちばん近い点までは 0.078（図の赤い線）
  • 100 点の中央値は 0.052
    • 軸の長さ 1 に対して 0.05 ほどなので、2 次元ではすぐ近くに点がある

次元を増やすと、いちばん近い点が遠くなる

  • make_data で 100 点を作り、特徴量を 2, 3, 5, 10, 20 個に増やして、いちばん近い点までの距離（中央値）を測る
for d in [2, 3, 5, 10, 20]:

    • k-NN が投票させる「近い点」が、実際には遠い点になっている
  • なぜこうなるのか、2 つの理由を見る

点は実行のたびに変わるので、手元の数字は少し違う

なぜ？　その1：真ん中に居続けられない

  • ある点が、ある軸で「中央寄り」（その軸の中央50%）に入る確率は \(\dfrac{1}{2}\)
  • \(d\) 次元で「全部の軸で中央寄り」でいられる確率は：

\[\left(\frac{1}{2}\right)^d \qquad \text{1次元: } 50\% \quad \text{3次元: } 12.5\% \quad \text{10次元: } 0.1\% \quad \text{20次元: } 100万分の1\]

要するに

  • ほぼすべての点が、どこかの軸では中央から外れている
  • 各軸を半分に切ると、空間は \(2^d\) 個の区画に分かれる（20次元で約105万個）
    • 100個の点は、ほぼ1個ずつ別の区画に入る
    • データは100万個の区画に散り散りになる

なぜ？　その2：「ご近所」の箱が各軸の大半にまたがる

  • 「近い点」を頼りにする手法のつもりで、周りのデータの1%を「ご近所」として集めたい
  • 各軸を割合 \(r\) だけ切り取った箱は、全体の体積の \(r^d\) を占める（点が一様なら、データの割合も \(r^d\)）。1% 集めるには：

\[r = 0.01^{1/d}\]

要するに

  • 10次元では、たった1%の「ご近所」を集めるのに各軸の63%を見渡す必要がある
  • それはもう「近所」ではない
    • 「近い点どうしは似ている」を前提にする手法（k-NN や k-means など）は、前提が成り立ちにくくなる

「近い」と「遠い」の区別が弱くなる

  • k-NN や k-means をはじめ、多くの手法は距離に依存している
  • 点を一様にばらまき、ある1点からほかの2000点までの距離を測る
  • 距離のばらつきを、変動係数（coefficient of variation）＝ 標準偏差 ÷ 平均 で比べる
import numpy as np
import matplotlib.pyplot as plt
import japanize_matplotlib

rng     = np.random.default_rng()
dims    = [1, 2, 3, 5, 10, 20, 50, 100]
cv_list = []   # 変動係数 = std / mean

for d in dims:
    pts   = rng.random((2000, d))
    query = rng.random(d)

次元の呪いへの対処

  1. 特徴量選択（feature selection）：重要な特徴量だけを残す
  2. 次元削減（dimensionality reduction）：情報を保ったまま次元を圧縮する
  3. 正則化（regularization）：過学習を防ぐ（線形回帰の回で扱う）

予測のたびに、全部の点までの距離を測る

  • k-NN の学習は、訓練データを取っておくだけ
  • その代わり、予測のたびに、訓練データの全部の点までの距離を測る（全探索, brute-force search）
    • 10 万点の実験では、テストデータ 1 点を予測するたびに、距離の計算が 10 万回
学習でやること 予測でやること
決定木 データから境界を作る 境界のどちら側かを見る
k-NN 訓練データを取っておくだけ 全部の点までの距離を測り、近い k 点の多数決を取る

質問

全部の点を測らずに、いちばん近い点を見つけるにはどうすればよい？

空間を軸で半分ずつに分ける（KD-tree）

  • 1 つの軸で点を並べ、真ん中の点の値で 2 つに分ける
  • 分けた両側を、次の軸でさらに分ける（特徴量 1 → 特徴量 2 → 特徴量 1 → …）
  • 箱の中の点が 5 点以下になったら止める
  • KD-tree（k-d tree）と呼ぶ
    • 決定木と同じく、軸に沿った線で空間を分ける木
    • k-d の k は特徴量の数（次元）で、k-NN の k とは別

KD-tree を作る

  • 関数の中で、同じ関数をもう一度呼ぶ（再帰, recursion）
    • 分けた片側を、同じ関数でさらに分ける
  • 木の各部分は辞書で表す
    • 分ける部分：分ける軸 axis、分ける値 value、小さい側 left、大きい側 right
    • 分けずに止めた箱（葉, leaf）：中の点の番号 points
def build_kdtree(X, idx, depth, leaf_size):
    if len(idx) <= leaf_size:                        # 点が leaf_size 個以下なら、分けずに止める（葉）
        return {"points": idx}
    axis = depth % X.shape[1]                        # 分ける軸：深さ 0 は特徴量 1、深さ 1 は特徴量 2、…
    idx  = idx[np.argsort(X[idx, axis])]             # その軸の値が小さい順に、点の番号を並べる
    mid  = len(idx) // 2
    return {"axis":  axis,
            "value": X[idx[mid], axis],              # 真ん中の点の値で分ける
            "left":  build_kdtree(X, idx[:mid], depth + 1, leaf_size),   # 小さい側を、同じ関数でさらに分ける
            "right": build_kdtree(X, idx[mid:], depth + 1, leaf_size)}   # 大きい側も同じ

tree = build_kdtree(X_train, np.arange(len(X_train)), 0, 5)
print(f"最初の分け目: 特徴量 {tree['axis'] + 1} = {tree['value']}")

近い箱から調べて、遠い側は飛ばす

  • ★ の入っている箱まで、分け目をたどって下りる
  • ★ の入っている箱の中の点と、距離を測る
    • いちばん近い距離を r とする（もっと近い点が見つかれば、r を更新する）
  • 分け目に戻るたびに、反対側を調べるか決める
    • 分け目までの距離が r より近い：反対側に、もっと近い点があるかもしれないので調べる
    • 分け目までの距離が r 以上：反対側の点は全部 r より遠いので、飛ばす

def search_kdtree(node, X, x, best):
    if "points" in node:                             # 葉：箱の中の点と距離を測る
        dist = np.sqrt(((X[node["points"]] - x) ** 2).sum(axis=1))
        best["count"] += len(dist)                   # 距離を測った点の数
        j = dist.argmin()
        if dist[j] < best["dist"]:                   # 今までより近い点があれば、入れ替える
            best["index"] = node["points"][j]
            best["dist"]  = dist[j]
        return
    diff = x[node["axis"]] - node["value"]           # 分け目から x までの、軸に沿った差
    if diff < 0:                                     # x は分け目より小さい側にある
        near, far = node["left"], node["right"]
    else:
        near, far = node["right"], node["left"]
    search_kdtree(near, X, x, best)                  # まず x のある側を調べる
    if abs(diff) < best["dist"]:                     # 分け目までの距離が r より近いときだけ
        search_kdtree(far, X, x, best)               # 反対側も調べる

def nearest_kdtree(tree, X, x):
    best = {"index": -1, "dist": np.inf, "count": 0} # r（best["dist"]）は無限大から始める
    search_kdtree(tree, X, x, best)
    return best

まとめ

  • k-NN：新しい点のラベルを、近い k 点のラベルの多数決で決める
    • 学習では境界を作らず、訓練データをそのまま取っておく
  • k はハイパパラメータ：k = 1 は訓練データで必ず当たるが、テストデータでは下がる（過学習）
  • 次元の呪い：特徴量を増やすと空間が広くなり、いちばん近い点も遠くなる
    • k-NN は当たらなくなり、点を増やしても追いつかない
  • KD-tree：軸で空間を半分ずつに分け、遠い箱を飛ばして、いちばん近い点を速く探す
    • 次元が高いと、飛ばせる箱がなくなる

  2. \(k = 1\) のときの予測を答えよ
  3. \(k = 3\) と \(k = 5\) のときの予測を、それぞれ答えよ

  • 距離は \(A\) が 1、\(B\) が 2、\(C\) が 2、\(D\) が 5、\(E\) が 5

  • \(k = 3\)：近い 3 個は \(A\)、\(B\)、\(C\) で、ラベル 1 が 2 個なので、ラベル 1
