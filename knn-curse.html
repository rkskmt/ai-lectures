近い k 匹の多数決にする（k-NN）

  • いちばん近い 1 匹だけに聞くと、その 1 匹に答えが左右される
  • 近い順に k 匹を選び、多いほうの種類を答えにする
  • k-NN（k-nearest neighbors / k 近傍法）と呼ぶ
    • 最近傍法は、k = 1 の k-NN
def predict_knn(Z_train, y_train, z, k):
    dist    = np.sqrt(((Z_train - z) ** 2).sum(axis=1)) # 新しい魚 z から、訓練データ全部までの距離
    nearest = np.argsort(dist)[:k]                      # 距離が小さい順に並べた番号の、先頭 k 個
    votes   = y_train[nearest]                          # 近い k 匹の種類（1=Salmon, 0=Sea bass）
    return int(votes.sum() > k / 2)                     # Salmon が半分より多ければ 1

質問

特徴量（次元）を増やし続けると何が起きるか？

次元の呪い

次元の呪い（Curse of Dimensionality）

  • データの次元が増えるにつれて、空間が指数的に広くなり、データがまばらになる現象
  • 2次元で十分だったサンプル数が、10次元では全く足りなくなる
  • 高次元空間は私たちの直感とは全く異なる振る舞いをする

ノート

名づけたのは Richard Bellman（動的計画法の発明者）。 現代機械学習でも最重要トピックの一つ。

準備

  • 各特徴量は 0〜1 に正規化してあるとする（各軸の長さ＝1）
  • そこに100個の点をランダムにばらまく
  • 点は「行＝点、列＝特徴量」の配列で持つ
  • まず特徴量2個（2次元）で、散布図に描く

距離を測る

  • 2点間の距離は、ユークリッド距離で測る
  • ある点から、ほかの99個の点までの距離をすべて測る
  • その中でいちばん小さいものが、いちばん近い点（最近傍, nearest neighbor）までの距離
def nearest_distance(P, i):
    dist = np.sqrt(((P - P[i]) ** 2).sum(axis=1))   # 点 i から全部の点までの距離
    dist[i] = np.inf                                # 自分自身は除外
    return dist.min()                               # いちばん近い点までの距離

print(f"点 0 からいちばん近い点まで: {nearest_distance(P, 0):.3f}")

nn = []
for i in range(len(P)):                             # 100個の点すべてで測る
    nn.append(nearest_distance(P, i))
print(f"100個の中央値: {np.median(nn):.3f}")

結果

  • 10次元で 0.70、20次元では 1.2。もはや「お隣さん」は存在しない
  • 同じ100点なのに。なぜこんなことが起きるのか、2つの理由を見る

なぜ？　その1：真ん中に居続けられない

  • ある点が、ある軸で「中央寄り」（その軸の中央50%）に入る確率は \(\dfrac{1}{2}\)
  • \(d\) 次元で「全部の軸で中央寄り」でいられる確率は：

\[\left(\frac{1}{2}\right)^d \qquad \text{1次元: } 50\% \quad \text{3次元: } 12.5\% \quad \text{10次元: } 0.1\% \quad \text{20次元: } 100万分の1\]

要するに

  • ほぼすべての点が、どこかの軸では中央から外れている
  • 各軸を半分に切ると、空間は \(2^d\) 個の区画に分かれる（20次元で約105万個）
    • 100個の点は、ほぼ1個ずつ別の区画に入る
    • データは100万個の区画に散り散りになる

なぜ？　その2：「ご近所」の箱が各軸の大半にまたがる

  • 「近い点」を頼りにする手法のつもりで、周りのデータの1%を「ご近所」として集めたい
  • 各軸を割合 \(r\) だけ切り取った箱は、全体の体積の \(r^d\) を占める（点が一様なら、データの割合も \(r^d\)）。1% 集めるには：

\[r = 0.01^{1/d}\]

要するに

  • 10次元では、たった1%の「ご近所」を集めるのに各軸の63%を見渡す必要がある
  • それはもう「近所」ではない
    • 「近い点どうしは似ている」を前提にする手法（k-means など）は、前提が成り立ちにくくなる

「近い」と「遠い」の区別が弱くなる

  • k-means をはじめ、多くの手法は距離に依存している
  • 点を一様にばらまき、ある1点からほかの2000点までの距離を測る
  • 距離のばらつきを、変動係数（coefficient of variation）＝ 標準偏差 ÷ 平均 で比べる

ノート

密度を保つには、次元数に対して指数的にサンプルを増やす必要がある。 1次元で10点あれば足りた密度を10次元で保つには、\(10^{10}\) 点が必要という計算になる。

ばらまいた点で、最近傍法を試す

  • 100個の点に、正解のラベルを付ける
    • 座標の合計が 1 より大きければ True、そうでなければ False（図の点線が境目）
  • 各点のラベルを、最近傍法で予測する
    • 訓練データとテストデータには分けず、自分以外の 99個の中から、いちばん近い点を探す
  • 100個の点すべてで予測し、当たった割合を出す
def nearest_index(P, i):
    dist = np.sqrt(((P - P[i]) ** 2).sum(axis=1))   # 点 i から全部の点までの距離
    dist[i] = np.inf                                # 自分自身は除外
    return dist.argmin()                            # いちばん近い点の番号

P     = rng.random((100, 2))                        # 100個の点を 2 次元にばらまく
label = P.sum(axis=1) > 1                           # 正解のラベル：座標の合計が 1 より大きいか

hit = []
for i in range(len(P)):                             # 100個の点すべてで予測する

「分散最大」と「垂直の足最小」は同じこと

各点で（中心からの距離）² ＝（軸上の影）² ＋（垂直の足）²（ピタゴラスの定理）。 左辺の合計はデータで決まっていて動かないので、影の分散を最大にする軸と 足の二乗和を最小にする直線は、同じものを選ぶ。

なぜ固有ベクトルなのか

「分散が最大の方向」を式にする

  • 探している直線の向きを、単位ベクトル \(\mathbf{v}\)（\(\|\mathbf{v}\| = 1\)）で表す
  • 中心化した点 \(\tilde{\mathbf{x}}_i\) のその直線への影（射影, projection）は、内積 \(z_i = \tilde{\mathbf{x}}_i^{\mathsf T} \mathbf{v}\)（ただの数）
  • 80匹ぶんの影は、行列とベクトルの積で一度に出せる：\(\mathbf{z} = \tilde{X} \mathbf{v}\)

知りたい「影の分散」を、少しずつ変形していく：

\[\text{影の分散} = \frac{1}{n-1} \sum_i z_i^2 = \frac{1}{n-1} \mathbf{z}^{\mathsf T} \mathbf{z} \qquad \text{（2乗和は「自分との内積」）}\]

\[= \frac{1}{n-1} (\tilde{X}\mathbf{v})^{\mathsf T} (\tilde{X}\mathbf{v}) = \frac{1}{n-1} \mathbf{v}^{\mathsf T} \tilde{X}^{\mathsf T} \tilde{X} \mathbf{v} \qquad \text{（転置の規則 } (AB)^{\mathsf T} = B^{\mathsf T} A^{\mathsf T} \text{）}\]

\[= \mathbf{v}^{\mathsf T} \underbrace{\left( \frac{1}{n-1} \tilde{X}^{\mathsf T} \tilde{X} \right)}_{C\;（共分散行列）} \mathbf{v} \qquad \text{（真ん中のかたまりに名前をつける）}\]

  • 共分散行列（covariance matrix）\(C\) は、影の分散を変形すると自然に現れる（ここが登場理由）
  • つまり PCA の探しものはこう書ける：

ノート

\(\|\mathbf{v}\| = 1\) のもとで \(\mathbf{v}^{\mathsf T} C \mathbf{v}\)（＝ \(\mathbf{v}\) 方向の分散）を最大にする \(\mathbf{v}\) を探せ

ノート

共分散行列 \(C\) も、これと同じ「対称な変換」のひとつ。 このあと、\(C\) の回らない方向こそが「分散最大の軸」だと分かる。

A の正体：回して・伸ばして・戻す

実は、この \(A\) は、おなじみの回転行列と軸ごとの伸縮だけで組み立ててある。

\[A = R\, S\, R^{\mathsf T}, \qquad R = \begin{pmatrix} \cos 45^\circ & -\sin 45^\circ \\ \sin 45^\circ & \cos 45^\circ \end{pmatrix}, \qquad S = \begin{pmatrix} 3 & 0 \\ 0 & 0.5 \end{pmatrix}\]

ヒント

対称行列はかならずこの「回転・伸縮・逆回転」の形に分解できる。これが固有値分解（eigendecomposition）。 np.linalg.eigh が返してくるのは、この \(R\)（固有ベクトル）と \(S\) の対角成分（固有値）。

答えが「固有ベクトル」になる理由

  • \(\|\mathbf{v}\| = 1\) は「\(\mathbf{v}\) の先端は半径1の球面の上」という意味
  • \(\mathbf{v}\) を少しだけ \(\boldsymbol{\varepsilon}\) 動かすと、分散 \(\mathbf{v}^{\mathsf T} C \mathbf{v}\) はこう変わる：

\[(\mathbf{v} + \boldsymbol{\varepsilon})^{\mathsf T} C\, (\mathbf{v} + \boldsymbol{\varepsilon}) = \mathbf{v}^{\mathsf T} C \mathbf{v} + 2\, \boldsymbol{\varepsilon}^{\mathsf T} (C \mathbf{v}) + \boldsymbol{\varepsilon}^{\mathsf T} C \boldsymbol{\varepsilon}\]

\(C\) は対称なので \(\mathbf{v}^{\mathsf T} C \boldsymbol{\varepsilon}\) と \(\boldsymbol{\varepsilon}^{\mathsf T} C \mathbf{v}\) は同じ値。\(\boldsymbol{\varepsilon}\) が小さければ最後の項は無視できる

  • 増える量は \(2\, \boldsymbol{\varepsilon}^{\mathsf T} (C \mathbf{v})\)、つまり \(\boldsymbol{\varepsilon}\) と \(C\mathbf{v}\) の内積の2倍
    • 内積は向きがそろうほど大きいので、分散がいちばん増える向きは \(C\mathbf{v}\)
  • 球面に沿って動くとき、\(\boldsymbol{\varepsilon}\) は \(\mathbf{v}\) と直交する
  • 球面上のてっぺんでは、球面に沿ってどちらへ動いても分散は増えない
    • \(\mathbf{v}\) と直交するどの \(\boldsymbol{\varepsilon}\) とも \(C\mathbf{v}\) の内積が 0 になるので、\(C\mathbf{v}\) は \(\mathbf{v}\) と平行になるしかない：

\[C \mathbf{v} = \lambda \mathbf{v} \quad \text{（固有ベクトルの定義式そのもの！）}\]

  • しかもそのときの分散は \(\mathbf{v}^{\mathsf T} C \mathbf{v} = \lambda \mathbf{v}^{\mathsf T} \mathbf{v} = \lambda\)。固有値＝その方向の分散

ヒント

  • 固有ベクトル＝「球面上でこれ以上増やせない方向」の候補リスト
  • 固有値＝その候補での分散の値
  • \(\lambda_1 \geq \lambda_2 \geq \cdots\) と並べて、一番大きい候補から PC1, PC2, … と呼ぶ
    • 対称行列の固有ベクトルは互いに直交するので、PC2 は「PC1 と直交する方向の中で分散が最大」の軸

  • レシピの1行目（PC1）は重さと体長を同じ重み（0.62）で足している
    • 「2つはほぼ同じ情報」を PCA が自力で見抜いた証拠。3行目（PC3）は重さ−体長の差分（0.71, −0.71）、だから空っぽ
  • Iris の3軸目を足しても累積寄与率は 95.8% → 99.5%
    • 2軸で十分の判断は変わらない

  • 特徴量を増やしても情報が増えるとは限らない：体長は重さの言い換えだった
  • PCA：分散が最大の方向（= 共分散行列の固有ベクトル）に軸を取り直す
    • 寄与率を見れば「データの実質的な次元」がわかる（魚は3次元に見えて実質2次元）

問題1の解答例

\(x\) 方向：平均 \(5\)、分散 \(= \dfrac{(-3)^2 + (-1)^2 + 1^2 + 3^2}{4} = \dfrac{20}{4} = 5\)

\(y\) 方向：平均 \(2.5\)、分散 \(= \dfrac{2.25 + 0.25 + 0.25 + 2.25}{4} = 1.25\)

損失関数：二乗誤差（MSE）

  • 各魚について「予測と実際のズレ」を測り、二乗して平均する

\[L(a, b) = \frac{1}{N} \sum_{i} \left( \underbrace{a x_i + b}_{\text{予測}} - \underbrace{t_i}_{\text{実際}} \right)^2\]

  • MSE（Mean Squared Error / 平均二乗誤差）と呼ぶ
  • クラスタリングの回の SSE と同じ発想で、誤差を 2 乗して集めたものを点の数で割った平均
  • 全魚のズレを1本のベクトルと見ると、MSE はそのノルム（norm・ベクトルの長さ）の2乗を \(N\) で割ったもの

損失関数は MSE だけではない

  • ズレの絶対値の平均でも「小さいほど良い直線」は測れる — MAE（Mean Absolute Error / 平均絶対誤差）
  • ズレの4乗の平均でもよい。「ズレが減るほど小さくなる」関数なら損失関数の候補になれる
  • 今回 MSE を選ぶ理由は微分のしやすさ：絶対値は 0 のところで折れていて微分できない。二乗なら微分がきれい
  • MAE での fit は外れ値に強い回帰で扱う

勾配を手で出す

\(L\) を \(a\) と \(b\) でそれぞれ微分する（合成関数の微分）：

\[\frac{\partial L}{\partial a} = \frac{2}{N} \sum_i (a x_i + b - t_i) \, x_i \qquad \frac{\partial L}{\partial b} = \frac{2}{N} \sum_i (a x_i + b - t_i)\]

  • 構造は単純：「予測と正解の差」を入力の大きさに応じて配る
  • あとは勾配降下法に渡すだけ：

\[a \leftarrow a - \alpha \frac{\partial L}{\partial a}, \qquad b \leftarrow b - \alpha \frac{\partial L}{\partial b}\]

数式とコードの名前

  • 数式では、勾配降下法の回と同じく学習率を \(\alpha\) と書く
  • コードでは、learning rateを略して lr と書く

勾配降下法で fit する

  • スケールを揃えてから（クラスタリングの回の教訓。学習率を1つで済ませるため）
#| echo: true

for i in range(1, 101):

正則化：大きい係数に罰金を払わせる

  • 暴れている曲線の正体は、巨大な係数
#| echo: true
plain = make_pipeline(PolynomialFeatures(9), StandardScaler(), LinearRegression())
plain.fit(X_train, y_train)
print("次数9の係数の最大絶対値:", f"{np.abs(plain[-1].coef_).max():,.0f}")
  • そこで、損失に「係数の大きさ」へのペナルティを課すことを考える：

\[L = \mathrm{MSE} + \lambda \sum_j w_j^2\]

  • このように、モデルの暴走を抑える罰則を損失に足す手法を正則化（regularization）という
  • MSE だけではなく、係数の大きさも loss に入れ込む
  • \(\lambda\)（ラムダ）が罰金の強さ。\(\lambda = 0\) なら今までどおりの MSE

正則化の実装：自作の勾配降下法に罰金を足す

  • sklearn には任せない。冒頭で自作した勾配降下法に、罰金の項を足すだけ
  • 罰金 \(\lambda \sum w^2\) の微分は \(2\lambda w\)。各係数の勾配に足せばよい
#| echo: true
# 特徴量 x, x², …, x⁹ も自分で作る（列が x^1 〜 x^9 の配列）
P_train = X_train ** np.arange(1, 10)          # 形 (10, 9)
P_test  = X_test  ** np.arange(1, 10)
mu, sd  = P_train.mean(axis=0), P_train.std(axis=0)
P_train = (P_train - mu) / sd                  # スケールを揃える（いつもの）
P_test  = (P_test  - mu) / sd
t_mean, t_std = y_train.mean(), y_train.std()
tt = (y_train - t_mean) / t_std                # 重さも標準化

lam  = 0.1        # 罰金の強さ λ
w, b = np.zeros(9), 0.0
lr   = 0.01
for i in range(10_000):
    pred   = P_train @ w + b
    grad_w = np.array([2 * np.mean((pred - tt) * P_train[:, d]) for d in range(9)]) \
             + 2 * lam * w                     # ← MSEの勾配 ＋ 罰金の勾配
    grad_b = 2 * np.mean(pred - tt)
    w -= lr * grad_w
    b -= lr * grad_b

test_pred = (P_test @ w + b) * t_std + t_mean  # 元の単位（g）に戻す
print("係数の最大絶対値:", f"{np.abs(w * t_std).max():,.0f}")
print("テストMSE:", f"{np.mean((test_pred - y_test) ** 2):,.0f}")
  • 係数の最大絶対値は 204,382 → 74。罰金が係数の暴走を実際に止めた
  • 勾配降下法のループは冒頭の自作コードと同じ形。増えたのは + 2 * lam * w の1項だけ

  • NN でも同じ道具がそのまま使われる（weight decay と呼ぶ）

  • 10：曲線はほぼまっすぐ寝て、訓練MSEまで悪化する（3,585 → 35,665）。罰金が強すぎて、訓練データに合わせる力が負けた
  • ちょうど良い \(\lambda\) は問題ごとに違う
    • 訓練MSEでは選べない（\(\lambda\) を小さくするほど下がるので、必ず \(\lambda = 0\) が選ばれる）
    • テストMSEでも選ばない（テストデータを確認してからモデルを調整しない）
    • 訓練データの中の交差検証で選ぶ（検証用に別のデータを用意しなくてよい）

問題1：魚2匹だけの世界で fit する

データは2点だけ：\((x_1, t_1) = (-1, 0)\)、\((x_2, t_2) = (1, 2)\)。 直線 \(ax + b\) を勾配降下法で fit する。初期値 \(a = 0, b = 0\)、学習率 \(\alpha = 0.1\)。手計算とPythonコードの両方で解け。

  1. 勾配の式に代入して、\(\dfrac{\partial L}{\partial a}\) と \(\dfrac{\partial L}{\partial b}\) を求めよ
  2. 更新を3回、手計算で示せ
  3. 同じ更新をコードで100回繰り返し、sklearn の答えと比較せよ

ヒント：2点を通る直線は \(y = x + 1\)。つまり答えは \(a = 1, b = 1\) になるはず。

問題1の解答例

準備（\(a = 0, b = 0\) での勾配）

予測は2点とも 0。差（予測 − 実際）は \((0 - 0, 0 - 2) = (0, -2)\)：

\[\frac{\partial L}{\partial a} = \frac{2}{2}\left[ 0 \times (-1) + (-2) \times 1 \right] = -2\] \[\frac{\partial L}{\partial b} = \frac{2}{2}\left[ 0 + (-2) \right] = -2\]

  • 反復1
  • 反復2
  • 反復3

\[a = 0 - 0.1 \times (-2) = 0.2, \qquad b = 0 - 0.1 \times (-2) = 0.2\]

差は \((b - a,\; a + b - 2) = (0, -1.6)\)：

\[\frac{\partial L}{\partial a} = \frac{2}{2}\left[0 + (-1.6)\right] = -1.6, \qquad a = 0.2 + 0.16 = 0.36\]

\(b\) もまったく同じ計算で \(b = 0.36\)。

差は \((0, -1.28)\)、勾配はどちらも \(-1.28\)：

\[a = 0.36 + 0.128 = 0.488, \qquad b = 0.488\]

\(a\) と \(b\) が揃って \(1\) に近づいていく。

#| code-summary: "解答例を見る"
import numpy as np
from sklearn.linear_model import LinearRegression

x = np.array([-1.0, 1.0])
t = np.array([0.0, 2.0])

a, b = 0.0, 0.0
lr = 0.1
for i in range(1, 101):
    pred   = a * x + b
    grad_a = 2 * np.mean((pred - t) * x)
    grad_b = 2 * np.mean(pred - t)
    a -= lr * grad_a
    b -= lr * grad_b
    if i in (1, 2, 3, 100):
        print(f"更新 {i:3d}回 | a={a:.4f} b={b:.4f}")

reg = LinearRegression().fit(x.reshape(-1, 1), t)
print(f"\nsklearn の fit: a={reg.coef_[0]:.4f}, b={reg.intercept_:.4f}")

手計算の3回（0.2 → 0.36 → 0.488）とコードの出力が一致し、100回で \(a = b = 1\)（sklearn と同じ）に収束する。

勾配降下法

進め方

  1. 目的関数（objective function）の意味を説明
  2. 勾配降下法（gradient descent）を1ステップずつ手計算
  3. Pythonで実装
  4. 調整値「学習率（learning rate）」を変えて、収束・発散の違いを確かめる

この関数の最小値を求める（目的関数）

\[f(x) = x^2 - 4x + 3\]

数学的には簡単だが、今回は数値的に（コンピュータのアプローチ）解く

目的関数（objective function）

最小化または最大化の対象となる関数

勾配降下法には滑らかな損失関数が必要

  • 今回は、目的関数 \(f(x)\) ＝ 損失関数
    • \(x\)：パラメータ
    • \(f(x)\)：損失関数
  • 勾配降下法では、傾きを計算できる滑らかな損失関数を使う
    • 滑らか = 微分ができるという意味

参考：分類で使う代理損失

  • 分類の学習では、予測の外れ方を連続的に測る滑らかな関数を使う
  • 誤分類数などの評価基準の代わりに最小化するため、代理損失（surrogate loss）と呼ぶ
  • 学習では代理損失を最小化し、評価には誤分類数や正答率を使える

基本方針：今いる位置から徐々に谷底を目指す

  • 今回の \(f(x) = x^2 - 4x + 3\) なら、グラフを描けば最小値は \(x = 2\) と一目で分かる
  • しかし実際の機械学習では、パラメータが多数ある。損失関数のグラフは描けない
  • グラフ全体が見えなくても、いまの位置 \(x\) で計算できる値はある：
    • 関数の値 \(f(x)\)
    • 傾き \(f'(x) = 2x - 4\)

今回の主題

足元の傾き（勾配, gradient）だけを頼りに、一歩ずつ谷底へ降りるのが勾配降下法

傾きの符号で進む方向が決まる

  • \(x = 0\) から出発する（別にどこからでもいい。今回はたまたま0）
  • ここでの傾きは \(f'(0) = 2 \cdot 0 - 4 = -4\)
  • 傾きが負 ＝ この場所では、右へ少し動くと \(f(x)\) が下がる（下り坂は右）
  • 谷底に近づくには、傾きの逆方向（傾きが負なら右）へ少し進めばよい

更新式

「傾きの逆方向に、少し進む」を式で書く：

\[x_{\text{new}} = x - \alpha \cdot f'(x)\]

  • \(x\): 現在の位置
  • \(f'(x)\): 傾き（勾配）
  • \(\alpha\): 学習率。1歩の大きさを決める正の数
  • \(x_{\text{new}}\): 次の位置

ノート

学習率 \(\alpha\) は自分で決める必要がある（これが難しい）

一旦、傾き0を目指す

更新式 \(x_{\text{new}} = x - \alpha \cdot f'(x)\) を、傾きの符号で場合分けする：

  • 傾きが負（下り坂は右）→ \(-\alpha \cdot f'(x)\) は正 → 右へ進む
  • 傾きが正（下り坂は左）→ \(-\alpha \cdot f'(x)\) は負 → 左へ進む
  • 傾きが0（谷底）→ \(-\alpha \cdot f'(x)\) も \(0\) → 動かない
    • 傾き0は山頂の可能性もあるが、下がってきて山頂は内という前提
      • ただ、初期値がいきなり山頂だと詰むので注意

要するに

  • 最大反復回数：終わらない場合に何回で打ち切るか
  • 停止条件：\(|f'(x)| < 0.01\) など、いつ収束したと判断するか

勾配降下法の動きを大きく変える学習率を中心に比較する

2変数では傾きが勾配ベクトルになる

  • 2変数では、それぞれの方向の傾きを偏微分（partial derivative）で求める
  • 偏微分を並べたベクトルが勾配

\[ f(w_1,w_2)=w_1^2+3w_2^2, \qquad \nabla f(w_1,w_2)= \begin{pmatrix} 2w_1 \\ 6w_2 \end{pmatrix} \]

\[ \begin{pmatrix}w_1\\w_2\end{pmatrix}_{\mathrm{new}} = \begin{pmatrix}w_1\\w_2\end{pmatrix} -\alpha\nabla f(w_1,w_2) \]

1変数との共通点

パラメータが増えても、各パラメータを個別に計算するだけ。１次元と変わらない。

\(f(w_1,w_2)=w_1^2+3w_2^2\) 最適化の可視化

  • \(w_1\) は谷の同じ側から近づき、\(w_2\) は谷をまたいで振動しながら収束する
  • 実際の機械学習の損失地形はこのさらに高次元版
    • グラフでは描けなくても、勾配ベクトルを使って各パラメータを地道に更新する

勾配降下法は主力アルゴリズム

  • 弱点（学習率の調整・遅さ）があるのに、勾配降下法はメインウェポン
  • 理由：パラメータが多数あっても、勾配を計算できれば更新できる
  • 実用では、パラメータごとに更新幅を調整する改良法（Adam など）も使われる

参考資料

  • もっと賢く進む手法もある → Newton法（2次微分で一気にジャンプ）
  • 谷が複数あるとき、どの谷に落ちるかは初期値しだい → ローカルミニマムの罠

まとめ

  • 最適化：評価基準が最も良くなるパラメータを探すこと。多くの fit() の中心にある
  • 勾配降下法：傾きを測り、逆方向に少し進む、を繰り返す

\[x_{\text{new}} = x - \alpha \cdot f'(x)\]

  • 学習率 \(\alpha\) は主な調整値：小さいと遅く、大きすぎると発散する
  • 初期値・最大反復回数・停止条件も決める必要がある
  • シンプルで軽く、大規模問題（ディープラーニング）の標準エンジンとなっている

次回予告

  • 今日手に入れた勾配降下法が、fit() の中身を開ける鍵になる
  • 次回、本物のモデル（線形回帰）を、この道具で自分の手で fit する
  • その先に分類モデル、そしてニューラルネットワークが続く。勾配降下法はディープラーニングを動かしている本物のエンジン

問題 出力の活性化関数
2クラス分類 シグモイド（1個の確率）
多クラス分類 ソフトマックス（10個の確率分布）

\[\mathrm{softmax}(u_k) = \frac{e^{u_k}}{\sum_{j} e^{u_j}} \qquad \text{10個の出力を「合計1の確率」に変換}\]

  • 損失は多クラス版の交差エントロピー：正解クラスの確率 \(p_{\text{正解}}\) に対して \(-\log p_{\text{正解}}\)（あの −log のカーブの10クラス版）
  • PyTorch では nn.CrossEntropyLoss がソフトマックスごとやってくれる（打ち消しの恩恵もそのまま）

スコアを実際にソフトマックスへ入れる

  • 3クラスのスコアを \(u=(2.0,\,1.0,\,0.1)\) とする：

\[e^u=(e^2,e^1,e^{0.1})\approx(7.389,\,2.718,\,1.105)\]

  • 分母は3つの合計：

\[7.389+2.718+1.105=11.213\]

  • それぞれを合計で割る：

\[\mathrm{softmax}(u) \approx\left(\frac{7.389}{11.213}, \frac{2.718}{11.213}, \frac{1.105}{11.213}\right) \approx(0.66,\,0.24,\,0.10)\]

Adam — 最適化回の伏線回収

  • Adam は、勾配の履歴を使ってパラメータごとに歩幅を調整する最適化手法
  • zero_grad → backward → step の形は、SGD と同じ

   ↓ Flatten
784次元ベクトル   (128, 784)
   ↓ Linear + ReLU
中間表現          (128, 128)
   ↓ Linear

  • 最後の 10 は数字0〜9それぞれのスコア

訓練画像60,000枚を128枚ずつに分けると：

\[\left\lceil\frac{60{,}000}{128}\right\rceil=469\ \text{ミニバッチ}\]

  • 最初の468バッチは128枚、最後の1バッチは96枚

  • したがって3エポックでは、約 \(469\times3=1{,}407\) 回更新する
  • shuffle=True により、各エポックで画像の順番を入れ替える

#| echo: true
for epoch in range(1, 4):
    loss_sum = 0.0
    for x_batch, y_batch in train_loader:
        optimizer.zero_grad()
        loss = loss_fn(model(x_batch), y_batch)
        loss.backward()
        optimizer.step()
        loss_sum += loss.item() * len(x_batch)

    # テストデータ（見ていない1万枚）で採点 — 過学習と汎化の回の鉄則
    correct = 0
    with torch.no_grad():
        for x_batch, y_batch in test_loader:
            correct += (model(x_batch).argmax(dim=1) == y_batch).sum().item()
    train_loss = loss_sum / len(train_ds)
    print(f"エポック {epoch} | 訓練Loss: {train_loss:.4f} "
          f"| テスト正答率: {correct / len(test_ds):.2%}")

自分の字は読めるのか（持ち帰りデモ）

紙に数字を書いて撮影し、この機械に読ませてみよう。 ただし写真をそのまま28×28に縮めても、まず読めない — MNISTの画像は「数字を20ピクセル角に収め、重心をど真ん中に置く」ように揃えてあり、撮った写真はそうなっていないから。同じ揃え方を自分でやってから見せる：

#| echo: true
#| eval: false
from PIL import Image
import numpy as np
import torch

# 1. 読み込み：グレースケール化して「インク=1、紙=0」に正規化
a = np.array(Image.open("my_digit.png").convert("L"), dtype=np.float32)
a = (a.max() - a) / (a.max() - a.min())

# 2. MNISTと同じ揃え方：数字を切り出し → 長辺20pxに縮小 → 重心を中央へ
rows, cols = np.where(a > 0.3)
a = a[rows.min():rows.max()+1, cols.min():cols.max()+1]
h, w = a.shape
s = 20.0 / max(h, w)
img = Image.fromarray((a * 255).astype(np.uint8)).resize((round(w*s), round(h*s)))
a = np.array(img, dtype=np.float32) / 255.0
x28 = np.zeros((28, 28), dtype=np.float32)
h, w = a.shape
x28[(28-h)//2:(28-h)//2+h, (28-w)//2:(28-w)//2+w] = a
ys, xs = np.mgrid[0:28, 0:28]
cy, cx = (x28*ys).sum()/x28.sum(), (x28*xs).sum()/x28.sum()
x28 = np.roll(x28, (round(14-cy), round(14-cx)), axis=(0, 1))

# 3. 推論
x = torch.tensor(x28).unsqueeze(0).unsqueeze(0)
print("予測:", model(x).argmax(dim=1).item())
